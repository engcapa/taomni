## Late body completion and operation feedback

The macOS `TC-MAIL-BULK-01` failure at step 14 retains 30 read message rows and
the status `Loaded body from server`. The initial repair guarded the manual sync
completion, but a body request can also finish after All read. Both delayed
cache and server body completions reproduce that overwrite in mounted tests.

`useMailFeedback` now owns the status and error state extracted from the mail
shell. It records whether a status is an operation result or loading feedback,
and atomically preserves operation results when body, header-cache or sync
loading completes. A new manual sync clears the previous result at invocation,
before waiting for any existing sync; its wait/completion feedback cannot erase
a read operation performed during that wait. This keeps the shell within the
800-line boundary without compressing or removing its existing behavior.

The mounted regressions verify delayed cache/server bodies, body text and read
flags, normal body loading feedback, the existing delayed-sync scenario and a
new manual sync superseding the previous operation. The retained QA case keeps
its original notice, read flags, selection, deletion and server-count assertions.
TypeScript, the frontend build and dependency/size/compatibility checks pass.

Final hosted verification will exercise the updated renderer in the three
platform browsers and the macOS native WebView where the race was observed.
The unchanged Windows/Linux native protocol and fixture assertions retain their
