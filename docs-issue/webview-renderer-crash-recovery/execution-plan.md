# 有限恢复执行计划

日期：2026-10-15，v3.1（文本优化独立）；**已实施检测/提示与受限恢复分支，原生和性能验收未执行**。以[主设计](../webview-renderer-crash-recovery-design.md)和[恢复矩阵](recovery-policy-matrix.md)为契约，尤其是DEC-09：小概率故障不值得大幅重构，能低成本恢复就恢复，否则提示；前端性能优先。

本次开发授权覆盖产品代码与本地单元测试；用户明确要求browser/native仅编写不执行。实际交付与证据见[实施报告](implementation-report.md)，全面用例见[测试映射](test-cases.md)。以下阶段0/原生探针/三端/性能步骤仍是未执行的验收计划；未授权触碰原白屏实例或启动多个agent。

## 1. 实施范围与优先级

| 优先级 | 交付 | 不满足条件时 |
|---|---|---|
| 必须 | 原生退出可检测、有原生提示、保留后台，不再让“白屏”完全没有解释；正常关闭/退出行为正确 | 某平台自动重建复杂就只提示，不杀主进程 |
| 优先 | 小型标签/终端描述、一次界面恢复、复用原session attach、现有客户端重连/状态读取 | 描述缺失、资源已结束或状态不明时对应标签提示 |
| 条件实现 | 当前画面/模式+500行，使用公开xterm能力和有界尾部 | 原型能力/性能失败就跳过对应状态，不自研完整终端状态机 |
| 不进入本次 | 全操作幂等、通用任务注册/事件重放、实时草稿镜像、精确协议回复账本、LSP/DAP迁移、框架升级、远程帧缓存 | 这些需求成为前提时，停止该恢复分支并提示 |

修改预期集中在现有窗口创建入口、TerminalPanel/terminal后端、App/MainLayout/appStore、少量IPC辅助及已确认危险的邮件恢复入口。矩阵里的几十个文件多数只是审计依据。开始某模块前先确认现有接口是否足够；不能因为列出功能就默认改它。

## 2. 阶段0：冻结证据和隔离环境

1. 记录R0基线源码、未提交差异、Node/pnpm/Rust、系统/引擎Build ID、真实加载库、构建flags及二进制hash。诊断旧release为v0.4.38/a20a2a0e，当前开发基线a11c227c，两者不能混充。
2. 复用私有诊断包，不再对正在白屏的实例做任何故障实验。新实验仅使用QA标识或独立OS账号/数据/工作目录；启动前核对app-data实际位置与PID归属。
3. 核对现有QA release构建强制debug_assertions的行为。功能探针可用它；R0/R1性能另用真实release flags，保持相同测量设施及相同文本镜像优化状态。Windows隔离不能仅改APPDATA，release不能依赖debug-only NEWMOB_DATA_DIR。
4. 先建立最小可重复负载：一个持续计数的PTY、一个vim/Codex类TUI、四/十六终端输出脚本、一个空闲客户端和一个原生后台服务。SSH额外需要明确opt-in及独立测试账号。
5. 捕获R0的正常输入/吞吐/帧与已有关闭、detach、startup/CWD行为。原生白屏缺陷用隔离renderer退出证明；自然GC错误不可稳定复现时准确区分两者。

产物：环境/构建清单、隔离位置、负载输入及R0原始结果。没有这些不写“性能无退化”，也不急于全App smoke。

## 3. 原TASK-07：已移交独立feat

终端自动全缓冲文本镜像优化已拆至[独立设计](../../docs-feature/terminal-buffer-text-performance-design.md)及[开发任务](../../docs-feature/terminal-buffer-text-performance/development-tasks.md)。保留原编号说明来源，本执行计划不承担其实现或验收，也不等待其完成。

## 4. TASK-01：最小原生探针、日志和失败提示

责任文件：`src-tauri/src/lib.rs`、`windowing/mod.rs`、独立SFTP窗口所在`filebrowser/mod.rs`；小型新模块可放`webview_recovery/`，只在需要时向`state.rs`加窗口恢复状态。依赖：阶段0；不依赖完整终端画面恢复。关联AC-01/05/06/08/09、V-01/03/04/07。

1. 接入Linux termination、macOS Tauri hook、Windows ProcessFailed；注册/注销与已有builder生命周期一致。在回调中排队，主循环执行动作；保存平台reason、时间和窗口身份。
2. 单窗口`healthy → recovering → ready/failed`及一次自动尝试、超时即可。重复回调合并；普通关闭标记优先；不增加心跳、通用scheduler和全应用IPC租约。
3. 在隔离实例验证事件后已有PTY存活、旧输出订阅可撤销、reload能否起新renderer，旧Channel队列是否有残留增长。先少量循环，出现证据再扩大定位；不是看到框架风险就先重写它。
4. Windows分别测renderer退出与browser退出。若现有Tauri公开API允许小范围重建则实现；如果需要patch框架内部或迁移所有特殊窗口，则这一路径改成原生提示，记录限制。
5. 不对截图/录屏覆盖窗使用通用销毁重建。main/普通分离/SFTP三个入口接入后，确认不存在关闭最后窗口顺便退出进程的问题。
6. 增加小容量release轮转日志与原生提示；死renderer无法弹React提示。恢复失败提供“重试界面/稍后处理”，关闭主窗口仍确认后台退出。

退出条件：三端分支语义明确、当前测试端回调/提示/后台保护成立。自动reload此时只用于隔离探针，未配合TASK-02/05之前不对用户默认开启。

## 5. TASK-03：先判断终端画面恢复值不值得做

责任：隔离原型、匹配xterm6的SerializeAddon/相关公开API评估；不先把依赖接入生产。依赖：R0基线与阶段0负载。关联AC-04/07/10、V-02/06。

1. 确认候选包版本/许可/当前xterm兼容；限定500行历史，单独核对主/备用屏幕、光标和实际输入模式。避免混淆xterm仓库tag与addon npm版本。
2. 两个终端接收同一流，在普通提示符、vim备用屏、Codex交互画面、UTF-8/CSI/OSC切分、resize时插入检查点；比较后续显示及方向键/粘贴/鼠标等输入语义。
3. 测80×24、160×50、240×80和宽屏压力；普通scrollback为10000，另测允许大配置，确认恢复复制规模不跟全历史增长。测同步耗时、p95/p99/最大值、分配与输入帧。
4. 测有界尾部能够覆盖的正常间隔；高速持续输出、超长控制序列、缺少安全解析边界允许受限。半包不能因为write callback结束就当完整。
5. 形成“直接可用 / 小适配可用 / 不恢复并提示”的能力表。协议查询回复、Taomni前置过滤及外部副作用无法简单隔离的状态列入受限，不增加完整parser/reply去重架构。

退出条件：输出有证据的能力范围和成本。常见场景通过才能实现对应分支；不通过就保留后台和界面恢复，不偷偷牺牲性能或假装纯文本等于完整TUI。

## 6. TASK-02/04：有限描述、启动握手和终端接回

责任文件：`src/main.tsx`/`App.tsx`选择一个公共bootstrap入口、`src/stores/appStore.ts`、`src/layouts/MainLayout.tsx`、`src/lib/ipc.ts`或小型`runtimeRecovery.ts`；`TerminalPanel.tsx`、`src-tauri/src/terminal/mod.rs`、必要的`state.rs`与分离辅助模块。不要求同时重构这些大文件；只提取当前恢复边界。依赖：TASK-01；检查点部分依赖TASK-03。关联AC-01至07/10、V-01至06。

1. 描述只含小型标签元数据、已保存配置引用、窗口归属和已知terminal ID；轻量增量合并。新建/关闭终端时尽量在现有后端边界登记；无法关联的在飞创建提示未知，不重新创建。
2. bootstrap先读取描述再挂载业务组件；恢复与冷启动分支明确，防Welcome默认值覆盖、组件mount自动新建。描述版本/instanceId不匹配走提示或现有冷启动契约，绝不复用跨主进程旧ID。
3. 复用adoptedTerminal/attach路径，必要时加窗口代次或恢复原因，防旧订阅/cleanup关闭现存终端。只保护相关资源入口，不把所有命令改成lease/requestId协议。
4. 通过TASK-03的状态才接入有界字节尾部、appliedSeq与checkpoint；关键是输出/快照边界连续。所有额外缓存有尺寸、字节、条目数上限，按需分配。没有预算就记录gap，不阻塞PTY，不给正常输出增加逐块IPC确认。
5. 恢复期间禁止外部副作用；确认画面/模式可用再启用输入。受限状态显示“后台运行，画面未完整恢复”；不自动Ctrl+L、重跑startup、再次SSH认证或创建shell。
6. 当前项优先，其余终端分批；客户端恢复独立且并发有界。高成本隐藏终端状态不无限保留，达到预算如实标缺口。
7. 正常close/detach/分离窗口归位与应用退出维持原行为。已有纯文本分离交接消费者不因为新方案被删除或无意改变。

退出条件：已支持普通终端恢复同一PID/ID，失败路径提示准确，正常生命周期不退化。一次不完整终端不阻塞其余界面；无须先解决全部TUI模式才能交付有限恢复。

## 7. TASK-05：按矩阵补少数守卫，不重写各业务

依赖：TASK-02恢复启动标记。关联AC-02/03/05/10/11/12、V-05/09/10。以矩阵为检查单，先标无需改动的功能，再改实际风险入口。

| 工作组 | 具体步骤与文件责任 | 停止扩张条件 |
|---|---|---|
| 客户端 | MainLayout路由/各tab只对恢复模式使用现有connect/读取入口；简单可查旧连接才清理重连。DBClientTab的unmount rollback/disconnect、对象存储close须防误停任务 | 旧事务/运行查询不可查就提示，不补通用查询任务表。隐藏页面待用户激活，无重复连接风暴 |
| Mail | `MailClientTab.tsx`接收恢复来源；Outbox自动处理在恢复启动中暂停，显示核对提示；读取既有草稿/缓存，正常冷启动逻辑保持 | 不增加SMTP事务、发送去重数据库、全局草稿同步；结果未知不自动发 |
| 后台控制面 | ServersDialog/serversStore、TunnelManager、SocksCapPanel复用现有查询与订阅；清理重复监听；检查恢复不会调用start_all/stop/boot_repair | 没有状态查询的任务直接显示未恢复，不统一改造所有manager |
| Git/Code/AI/下载 | 已保存路径/文件/消息/任务信息能直接读就读，缺失显示限制；回放、重跑、安装和权限请求不自动触发 | 不重构LSP/DAP、插件Update资源、下载管理或AI事件存储 |
| 特殊窗口/采集 | screenshot、voice、lanchat已有status/stop/落盘入口，处理失去控制的采集；确认普通窗口恢复不误触Destroyed删除 | 不建设全应用窗口替换事务；复杂控制状态不恢复，沿已有停止能力收尾 |
| 非持久UI | settings/notes/文件编辑/宏/Quick Connect等重读已有保存结果或提示丢失，防初始空值写回 | 不增加逐字符镜像；无副作用的展开/选中/图表状态可丢失 |

退出条件：26/21/9分类完整，实际副作用入口有守卫，现有可读状态恢复；支持与提示两种结果均明确。不是要求每个后台任务都有可查询进度。

## 9. 发布、回退与完成判定

建议分开可审阅的改动：恢复检测/提示与有限描述；通过原型的终端接回加少数副作用守卫。生产文本镜像优化由独立feat交付，不混入这些改动。实际拆分按可独立验证边界决定，不要求固定提交数。裸reload必须等恢复启动守卫准备好才启用。

按平台/能力启用有限恢复；某端自动重建不合适就保留原生提示。失败可以关闭自动恢复或检查点，不影响原任务，不改成重启应用。恢复内存结构不做磁盘迁移，既有用户数据格式不因本次扩大。

完成时明确列出：哪些状态能恢复、哪些按DEC-09提示、性能结果、各平台实测/未验证范围。主进程保活、没有重复操作、准确提示、无前端性能退化是底线；完整保留所有业务中间态不是本次完成条件。若某项需要明显超出这里的局部改动，选择提示并记录原因即可，不另行扩张实现。
