## Original evidence

The original `qa-summary-62bee337a46648c48e7e627c3286f3ac` contains 2,521 selected executions: 2,327 passed, 79 failed across 28 distinct case IDs, and 115 produced no case result because two Linux shards failed during preparation. The three build producers and native/tool contracts passed. A successful execution job only means its report is complete; case failures must be read from `ci-summary.json`.

The large failure count is amplification of shared setup/state errors across platforms and later cases. Proxy contamination accounts for 59 failed executions across 24 case IDs; outdated SSH select assertions account for 16 (TC-124/148), the obsolete icon assertion for three (TC-133), and two-instance Wayland focus for one (TC-MAIL-PERF-03). The 115 unexecuted selections are a separate desktop/service ordering failure. For example, the VNC shard 3 terminal targets SSH `127.0.0.1:32768`, but both its terminal and DB EXPLAIN fail against `127.0.0.1:36201`, the previously stopped proxy. These are not 79 independent product defects.

| Failure mechanism | Evidence and fix |
|---|---|
| Desktop starts after display-dependent services | VNC shard 2 (58 cases) and Wayland shard 2 (57 cases) fail in `prepare`: `X11 acceptance requires the invocation's real display`. Unlike outer Xvfb, these profiles create DISPLAY inside `Desktop`. Start the desktop before `Services`; close services before their desktop. |
| Linux configuration leaks across cases | AI model-inspector fixtures write the application proxy at `XDG_CONFIG_HOME/taomni/proxy.json`, outside `com.taomni.app.qa`. Existing reset only removed the application-ID directories. Subsequent DB, mail, SSH and xrdp errors all target the stopped gateway (e.g. `127.0.0.1:41651` in Linux shard 1), regardless of their actual service port. Reset run-owned Linux `taomni` configuration/cache namespaces too, validating every target before deleting any. |
| SSH form assertions use old presentation values | TC-124/148 expect `Custom command…`/`Disabled` as DOM values. Production `SshSettings` now uses stable values `custom`/`disabled`, retaining the translated labels. Select each label and assert its stable value before and after saving; replace positional selectors in TC-124 with existing test IDs. |
| Bookmark assertion predates custom-icon support | TC-133 expects the custom-icon button to be disabled, but `BookmarkSettings` now implements its picker. Assert enabled, retaining all dialog cancellation and save/reopen checks. |
| Wayland cannot distinguish two QA instances | TC-MAIL-PERF-03 window-activation diagnostics show normal windows from PIDs 33144 and 33280 sharing the same binary/compositor. Capture each session's XDG data directory before a peer harness changes the environment, and include it in broker matching. Preserve executable, runtime, toplevel uniqueness and observed focus checks. |

## Additional boundaries exposed by the full rerun

The first rerun removed the original broad connection failures and allowed previously blocked shards to execute. It also exposed these additional automation defects; their failures remain recorded in that run:

- `TC-MAIL-POP3-01` on Xvfb delivers three new messages while the initial sync is still finishing. Its pointer trace has pointer-down/up on the disabled Sync button but no click event; after 60 seconds the server has 33 messages and the UI still has the initial 30. Wait for an enabled Sync button before delivery/clicks and for completion of each requested sync, retaining the exact server/list equality and UIDL de-duplication checks.
- `TC-SESSION-GSS-001` on Wayland opens a real detached SFTP window. Both normal windows share one PID/profile, so profile matching alone still finds two. Read the current WebDriver context's native title with the existing permitted Tauri window API; match profile, executable, compositor and title, and observe focus of that exact window. `document.title` is shared by packaged pages and cannot identify the native window. Duplicate matches still fail.
- `TC-SESSION-BOOK-003` on Xvfb clicks Reattach, which can close the source WebView before WebKit returns the element-click response (`no such window`). Extend the existing `switch_window` owner with explicit `close_with`: click once, require the source handle to disappear, then find the main window. Other driver failures and a source that remains open still fail; no click is replayed. The retained terminal-count and standalone-output assertions verify the actual handoff.
- `TC-RDPJ-01-client-server-loopback` on macOS connects and displays the real desktop, but the independent host target records zero flips. Its trace shows pointer move/down/up in one millisecond, despite the requested 50ms move and 60ms pause. A new timing regression reproduces this: the QA-only WKWebView bridge ignores action durations. Honor the longest source duration per W3C tick and await the whole action sequence through an owned completion slot; remove the slot on failure/timeout so later ticks stop. Existing pointer compatibility, modifier, hover, drag, context-menu and double-click behavior is retained. Production RDP input code is unchanged; the hosted rerun must establish actual host input.
- `TC-SESSION-SCP-003` on macOS resumes into an already completed transfer before the running-state assertion observes it. The 4,915,200-byte file is transferred in well under a second; the old remote `scp -l` wrapper does not reliably bound that host's stream and does not cover the Python suffix source. Use a dedicated run-owned TCP link at 256 KiB/s for this lifecycle case, forwarding real encrypted SSH bytes in both directions. Other SSH cases keep the direct port. Closing services interrupts sockets and rate waits. Retain pause, background ownership, cancel, retry, nonzero resume offset and exact SHA256 assertions.

Follow-up local verification: 131 window/focus, WebDriver transport/fill, native assertion and reporting contracts passed; 49 service/link/window contracts also passed (overlapping suites, not additive). Nineteen exact embedded QA pointer/keyboard tests passed, including timing and cancellation. The new timing assertion fails against the previous bridge. Browser POP3 passed (1/1, 17.9 seconds, stable identity). `cargo fmt --manifest-path src-tauri/Cargo.toml -- --check` and source boundary checks passed. Final hosted evidence is recorded below. ## Intermittent failures during the replacement full run

The selection manifests have been compared by group and exact case IDs: all original 2,521 case/platform/mode/desktop selections are retained. The full run's initial failures remain recorded even when a later focused execution passes; the runs are not combined into a claim of one clean full run.

- Linux Ubuntu 22.04 X11 `TC-RDPJ-01-client-server-loopback` reached the real host (`target-state.json` has `flips: 1`), entered full screen and received measured network quality. The retained log has no native stack or precise crash cause, so the crash is not attributed to a connection-bar defect. This establishes a passing re-execution, not a proven fix for the intermittent WebKit crash.

Connect was 68 ms, animation 30.68 fps and bandwidth 600.66 kbps, all within their original budgets. The same commit's focused run https://github.com/engcapa/taomni/actions/runs/40093890875 passed (1/1; `report_ok=true`, `passed=true`): 40 samples, zero timeouts, p95 53.41075 ms, max 57.146209 ms, connect 89 ms, 35.56 fps and 708.25 kbps.
