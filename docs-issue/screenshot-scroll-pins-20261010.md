# 滚动截图与贴图编辑修复（2026-10-10）

关联问题：[滚动截图 #695](https://github.com/engcapa/taomni/issues/695)、[Ubuntu 自动滚动抢鼠标 #694](https://github.com/engcapa/taomni/issues/694)、[Ubuntu 多屏截图 #693](https://github.com/engcapa/taomni/issues/693)。

## 原因与处理

- 视频列表中的悬停播放、缩略图更新会持续改变局部像素。原稳定性判断要求所有采样区域静止，重叠匹配对动画像素也过于敏感。现在允许少量内部区域变化，保持边缘严格检测，并限制异常像素对匹配分数的影响；广泛布局变化仍需要恢复重叠。
- 鼠标只需位于能收到滚轮的目标区域内，无需位于中心。自动模式保留选区内已有鼠标位置，否则只初始化一次靠右的位置。鼠标移出选区暂停，移回继续；Wayland portal 不再在每个滚轮前强制移动鼠标。
- 自动滚动采用一格步长，页面还在变化时等待，不继续注入滚轮。疑似到底后等待两秒并再次尝试滚动，以处理已经加载到当前视口下方的新内容。仅靠屏幕像素不能判断任意网站的网络请求何时完成。
- 手动采样间隔从 120ms 降至 40ms，稳定复查从 80ms 降至 50ms。快速滚动跨过整个重叠区域时，缺失像素不能从之后的画面恢复；保留可靠锚点、提示向上回滚，不直接拼接未知区域。提示建议每 0.5 秒一格、每次不超过选区高度三分之一，等图片加载后继续。
- 滚动结果与贴图编辑使用有系统边框、可缩放的普通窗口，初始大小约为屏幕的 80%。
- 贴图更多操作迁入独立、可缩放的设置窗口。贴图 renderer 继续持有缩放、透明度、备注等状态，通过窗口事件与设置窗口通信；关闭源贴图会关闭其设置窗口。
- 贴图编辑记录源贴图。Done 提供覆盖原贴图、新建贴图、仅复制，三种都写入剪贴板。覆盖使用独立新文件并更新源贴图，保留备注；收藏仍是原像素的独立快照。失败保留编辑，取消与窗口关闭恢复被隐藏的贴图。
- 选区界面增加显示器选择，可切换到负坐标显示器，无需先移动主窗口。

## 验证与边界

本机使用独立 `com.taomni.app.qa` 应用、当前工作区构建身份与隔离的数据目录。原生断言覆盖实际屏幕像素、滚轮、窗口几何、系统剪贴板、保存对话框和收藏文件。`TC-SHOT-N16` 检查滚动编辑窗口缩放；`TC-SHOT-N17` 检查独立设置窗口及 Done 三条路径。

首次本机 native 运行 7/8 通过；新增编辑测试点击后设置窗口关闭，脚本回复超时。修正为先等待控件，再发送不依赖关闭窗口回传的点击。失败证据保留。

已在用户登录的 Chrome YouTube 主页完成真实区域截图和原生滚轮初测：选区 1633×778，自动模式输出 1633×2478，手动每 0.5 秒一格输出 1633×3478，两次未触发重叠丢失。最终构建再次完成自动、慢速手工及极快速手工测试，鼠标坐标记录确认没有被拉回中心。极快速测试每 50ms 八格，触发重叠丢失并保留已确认内容，未把未知区域直接拼入结果。网页内容会随账号和时间变化，此结果不保证所有选区、所有页面都成功。

本机检查：39/39 browser 截图用例通过；6 个前端测试文件共 59 项通过；87 项 Rust 截图测试通过。最终构建 8/8 native 用例通过，包含窗口缩放、Done 三条路径、像素与系统剪贴板比较。新增/调整用例、控件目录、CI selection plan 与 `audit --gate` 通过。全仓 `cargo fmt --check` 仍报告包括未修改的 sockscap、VNC 等模块在内的既有格式差异；本次滚动算法文件已单独 rustfmt。全仓前端测试误触发时出现与初始基线相同的 Terminal/VNC/ChatDrawer 失败，已停止该运行；不把它作为本次截图验证通过的证据。

本机仅检测到一个 1920×1080 显示器。多屏用例 `TC-SHOT-039` 验证 renderer 的选择与 IPC；不能代替真实 Ubuntu 双屏和混合 DPI 验收。Wayland 单屏、窗口与 portal 行为由 GitHub 的 Ubuntu 26.04 Wayland profile 补测。
