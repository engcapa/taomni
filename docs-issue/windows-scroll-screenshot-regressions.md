# Windows 滚动截图修复与验证

范围：用户报告的 Win11 全屏/当前窗口自动滚动、自动与手动拼接重影、多开快捷键和无法停止问题。参照 `v0.4.34`，工作区基于 main（`a6ed86731fce2c4d72326b69eea0416b3956443a`）。普通单帧截图作为保留行为验证。

## 定位结果

- `scroll_layout` 在没有外部控制窗位置、且启动快捷键未注册时，从选区底部扣除 200 逻辑像素及间隔。此分支在 v0.4.34 中也存在；多开时后启动实例注册失败，就会触发不同布局。不能将这个现象全部归因于 main 新增代码。
- 自动滚动每一步重新移动鼠标到选区中心，导致鼠标难以到达停止按钮。全屏隐藏控制窗的退出操作又复用了启动截图的全局快捷键；全局注册属于另一个实例时，会启动另一个截图界面。
- 当前窗口外框包含固定侧栏、滚动条及窗口边缘。原拼接对整行取均值，固定侧栏影响位移匹配，变化的滚动条影响底部固定区判断。Win11 原生探针中完整窗口能滚动，但明确出现右侧滚动条、底边重复，证据见 `qa-ui-auto-report/screenshot-win11/baseline/`。用户实际页面不滚动未在这个简单页面复现，另以带固定侧栏/变化滚动条的回归测试约束失效机制。
- `GA_ROOTOWNER` 可能将待滚动窗口解析成另一个所有者窗口；现在使用实际的顶层 `GA_ROOT`，并在首帧前激活目标，避免首帧是不活动边框、后帧是活动边框。
- 之前 Win11 每帧创建/关闭一次 WGC 捕获会话；手动模式每 120ms 直接尝试拼接。现在保持一个捕获流，并以局部像素块检查相邻两帧稳定性，避免大面积中心匹配掩盖窄边缘过渡。共享捕获器原有的 250ms 空闲等待与稳定性复查叠加，会错过连续手动滚动的重叠；滚动截图现在自行控制采样间隔，只转换选区的像素，并立即读取最新帧。RDP 和录屏仍使用原来的等待行为。
- 仅追加新帧尾部会把上一帧视口底部的圆角、滚动条箭头留在长图中，这不是正文位移匹配错误。现在在已确认的重叠中部接合，替换旧视口底边；从实际位移识别固定两侧，有连续空白背景时保留其控件一次、在空白处延长高度，不缩放控件、不裁窄选区。没有可确认空白的复杂侧栏保持原始接缝像素。
- 窗口外的复杂桌面背景可能让整个侧带找不到空白，导致一小段滑块仍留在接缝中。再按同位置像素是否变化区分滑块与固定背景，分别合成；单测加入邻接复杂背景的场景，原生断言同时检查按钮次数和滑块/箭头的纵向像素数量。
- Win11/WebView2 前台属于 Taomni 时，同进程低级输入钩子收不到停止键。原生失败证据保留；最终方案复用仓库 VNC 已验证的独立辅助进程模式，监听 Esc/右键。辅助进程没有窗口，不启动第二个应用；管道关闭即退出，覆盖父进程退出。

## 新行为

- Windows 全屏或大选区完整保留；放不下提示窗时隐藏提示窗，启动快捷键是否注册不影响选区。
- Esc 完成滚动并保留结果预览；Windows 右键同样完成。取消按钮仍丢弃滚动结果并返回原截图。按键/鼠标释放也被消费，避免同一个操作关闭预览或打开目标的右键菜单。
- 自动滚动只在首次建立目标时移动鼠标；鼠标移出选区暂停，移回继续。启动截图快捷键不再停止滚动。
- 桌面截图会话由进程间文件锁协调，已有活动截图时其他实例不能再开启覆盖层。锁由 OS 管理，进程崩溃不会留下永久占用。独立录屏入口也遵守该锁。
- 拼接匹配排除窄边缘和不移动的列，仍保留输出宽度；底部固定区域只在末尾出现一次，固定侧边的箭头、滑块和边角避免逐帧重复。相邻稳定采样用于自动、手动两种模式；过渡帧不作为新锚点，自动模式等待稳定时不继续注入滚轮。

## 其他快捷键排查

仓库只有截图使用 `tauri_plugin_global_shortcut` 注册系统全局组合键。应用快捷键通过当前 WebView 的键盘事件处理，不会广播到其他实例。VNC 特殊键辅助进程额外校验前台窗口 PID，只向自己的父实例转发；截图 Esc 使用不同的临时会话监听。启动快捷键注册失败后的应用内回退仍保留，并由后端会话锁去重。录屏原有启动组合键完成路径保留，录屏会话同样阻止其他实例开启截图。
