# Shared AI configuration and ordinary Tao providers

Current acceptance is recorded in [R16 platform verification](verification-md-history-agent-2026-11-17.md#r16-wrapped-export-notice-and-fast-reply-history): affected units, all three browser selections and matching native release selections have passing final case results, including complete crash regressions. Windows results combine the main run with the unchanged-input recovery; the original setup timeout remains retained. Ordinary-provider native OS attachment/branch HOME045/046 remain Linux/Windows acceptance only. Commercial OpenCode results are separately versioned and do not certify every configured provider's commercial endpoint.

The existing LLM configuration and Tao chat defaults now appear in one Settings panel, with one live AiStore draft and one Vault-aware save. Endpoint, model, multiple API keys, model inspection, capability flags, provider groups and the three proxy modes remain in the LLM provider rows. Tao defaults retain enablement, provider/model, thinking/effort, web, title, speech recognition, TTS voice, cost threshold and privacy/source controls. Privacy source changes continue using their existing immediate persistence API. The `ai-tao` deep link remains valid within the combined panel.

No configuration-file migration or duplicate credential store is introduced. The legacy `deepseek_app` field remains readable. Frontend normalization preserves ordinary provider IDs rather than coercing them back to DeepSeek. Vault saves take the latest shared draft after unlocking; the form disables while saving. No inference is sent merely by saving configuration.

Tao selects configured chat LLMs using OpenAI-compatible, Anthropic, llama-server/Ollama, DeepSeek Messages or OpenCode Go runtimes. Claude Code, Codex, ACP, provider groups, unknown runtimes and media-only providers are excluded. Fully disabled AI yields no choices; full-local mode exposes loopback endpoints only. Local endpoints can work without an API key. Existing threads retain their provider, model and capability choices; a missing provider is shown as unavailable, without silently rerouting its request. A new conversation can fall back to an available configured default. Ordinary chat explicitly disables Tao-specific thinking/web switches, including when choosing Act or Research; the backend rejects unsupported flags as well.

The ordinary protocol adapters reuse Tao's run/cancellation, persisted request/history, context redaction, privacy gates, confirmed actions, partial checkpoints, stop/regenerate/continue and settlement owners. They use Settings' shared native proxy resolution and Vault credentials. They do not invoke a harness or duplicate the action executor. HTTP errors and interrupted streams remain visible; no automatic paid retry or direct proxy fallback is added. OpenAI finish reasons and usage-only tails use the existing normalized stream accumulator; Anthropic uses the Messages accumulator.

Local attachments gain a provider ownership column, migrating prior entries to `opencode-go` idempotently. IDs and lookup include conversation/provider ownership. Switching provider removes current file chips and replaces foreign historical attachment handles with an explicit omission marker in the outgoing context, preserving conversation text. Reading the document on the new provider requires selecting it again. File bytes remain local until a question is sent; current paths/hashes are revalidated before conversion. Ownership metadata never enters the external Messages source object.

Native HOME046 reproduced a branch losing its original attachment authorization. Branch creation now persists exact grants for retained user attachment blocks and the saved composer selections, only if the source already holds the same file/provider authorization. An unrelated file, omitted later message or foreign provider cannot acquire a grant. Recursive branches retain explicit authorization after reopening SQLite; deleting a branch removes its grants, and explicit file deletion revokes every inherited reference. Re-selecting identical original bytes updates the file record without deleting it or cascading away existing grants. Every read still validates current disk bytes. Snapshot, canonical messages and grants commit in one transaction; a failed insert rolls them all back. Public IPC names, root attachment IDs and existing file metadata stay compatible.

SQLite attachment ownership is extracted into `inline_files/storage.rs` with explicit typed file records; asynchronous filesystem validation/document conversion remains in `inline_files.rs`. The storage module does not import the conversation facade. Its dedicated test module covers grant boundaries, legacy Go defaults, recursive/reopened branches, scoped deletion, hash changes, reselection and rollback. The six added tests pass with the retained 40 backend tests. The native failure before the change is preserved in `run-20261117-082741-335445161`; matching QA release verification follows the fix.

The provider row was extracted from the LLM panel into `LlmProviderRow.tsx`, with typed inputs and shared field helpers. The panel retains save/Vault/retry ownership; Tao defaults edit only their fields through `updateTaoDefaults`. This avoids two full-config drafts overwriting each other. There are no reverse imports from the row into its panel. New modules remain below the repository's 800-line boundary.

Unit regressions cover ordinary provider filtering/defaults, actual shared configuration serialization, capability gates, thread restoration, API wire conversion, attachment schema migration/ownership, foreign history omission and stripping local wire metadata.
