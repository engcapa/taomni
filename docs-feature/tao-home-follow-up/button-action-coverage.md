本矩阵同时保留尚无足够验收的条件能力：工作流实际阶段执行与运行中取消、真实语音和管理员提升。新增用例失败要先区分产品与 fixture，修复后保留原失败回执。商业 Key 不进入此文档或 GitHub；本批商业启动如受自动审批拦截，必须记未执行，不能套用用户对“凭据已失效”的成功例外。

补充用例发现并保留的失败：032 在 Windows 取消后仍留下实际 Python 子进程，修复为 Windows Job Object / Unix 独立进程组的完整生命周期清理，并覆盖 future 被丢弃、真实退出码和输出；010 从已打开的 Tao 设置搜索 theme 后仍停在旧区域，改为复用异步标题定位，查询清空或用户接管时释放。033 原先使用通用 tab selector，已按实际 workspace-tab 契约更正，同时核对选中目录的真实 root path；原失败不是目录未打开。

记忆/技能编辑改为原生侧栏内的受控表单，保留条目身份与类别；保存进行中禁用重复提交和取消，失败保留草稿供重试，取消按钮与 Escape 都不修改已保存资料。异步加载和操作结果按组件生命周期与请求代次校验。034 全程使用实际 UI、IPC 和文件保存选择器，不替换 prompt，也不直接调用保存接口。

实际批次、source/build/runner 身份和截图见 [开发闭环验证](verification-agent-loop-2026-11-16.md)。本文件为用例映射，不宣称所有条件按钮及原型已整体达到生产验收。
