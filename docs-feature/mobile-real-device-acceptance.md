## 执行顺序与需要用户提供的条件

1. 先完成当前源码/runner 的 hosted browser/native 全部选例及独立报告核验。
2. 在同一产品版本上执行下面的真机与真实飞书场景；证据注明版本，不与旧报告混合。
3. 若暂缺手机、HTTPS 或飞书测试应用，标记具体未验证项，不用模拟结果替代；这些外部条件准备期间可以继续独立的 Mobile Web 多语言开发，但后续真机复验要使用新的实际版本。

需要用户确认的信息（不需要任何秘密）：

- 可操作的 Android Chrome / iPhone Safari，系统及浏览器版本；是否两类设备都可提供。
- 实例端 OS，以及手机与实例是否同一局域网；是否已经有手机能到达的 HTTPS 地址、第二实例地址。
- 是否有可用的飞书企业自建测试应用、测试用户和专用私聊/测试群；当前是否已发布并开通消息和卡片回调权限。

**不要把 App Secret、设备 token、配对码、私钥或保险库主密码贴进聊天/Issue/验收文件。** App Secret 由用户在实例本机的 Settings → Network → 飞书适配器中输入并保存到凭据库；手机不输入保险库主密码。真实发消息、审批与可能消耗模型额度的动作，在执行前明确测试目标、内容和授权。

## 安全准备

- 使用可丢弃的 QA 工作区、终端、Agent 线程和测试文件；不对个人生产任务停止、输入或审批。
- 原生验证使用匹配源码的独立 QA release（`com.taomni.app.qa`）和隔离测试数据，参考 `.agents/skills/qa-ui-auto/references/native-testing.md`。具体启动配置按实际 OS 准备，不用重命名生产程序伪造隔离。
- 默认关闭移动服务；测试才开启。远程手机需要显式开启 LAN 或使用用户自备反向代理，不替用户开放互联网端口、变更系统代理或部署中继。
- LAN HTTP 是明文，只可用可丢弃数据验证手动配对/基础操作；扫码、Service Worker/PWA、剪贴板读取需 HTTPS 或 localhost 的安全上下文。手机访问 PC 的局域网地址不等于 localhost。
- HTTPS 外壳不能调用 HTTP 实例。反向代理保留外部 Host 时，先按 `mobile-remote-p0-implementation.md` 配置实际 profile 的 `mobile-listener.json` `allowed_hosts`；不要填写泛域名或关闭 Origin/鉴权校验。
- 记录现有设置，结束后吊销测试设备、停止测试服务及飞书连接；仅清理明确自有测试数据。

## 真实飞书 V-08 步骤

### 应用与权限

- 独立企业自建测试应用，每个 Taomni 实例使用独立 App ID；当前不支持靠同一 App 的集群随机分发选择多实例。
- 启用机器人、发布到测试用户；订阅 `im.message.receive_v1` 与 `card.action.trigger` 长连接事件。
- 所需权限为 `im:message:send_as_bot`、`im:message.p2p_msg:readonly`；群聊接收需相应群消息权限。群聊机器人 mention 入口尚未适配，现有群聊按 `/taomni` 前缀契约验证，不修改期待冒充支持。
- 由用户在实例本地保存 App Secret 与 `open_id chat_id` 白名单。配置中明确 Mobile Web HTTPS 地址和三种代理之一；保存设置不应自动外联，显式启动连接。
