## 数据与实现契约

- SQLite 仍按 session 分库。完整邮件映射记录 folder、UIDVALIDITY、UID、SHA-256、原始/压缩字节数及完成时间；完成的原件不可变，临时文件与已发布文件分离。
- 原件位于 `<storage>/<session-stem>.mail/objects/<hash 前两位>/<hash>.eml.gz`。先完整写临时文件并校验，再原子发布和提交映射。没有完成映射的临时文件不能当作已保存邮件。
- 下载使用 IMAP BODY.PEEK 的分段读取，部分文件按 folder/UIDVALIDITY/UID 标识，恢复时核对服务器身份和大小。后台任务单账号去重，分段释放连接，解析与压缩在阻塞线程。
- 已缓存摘要保持快速查询。原件是离线内容的权威来源，最近正文是可重建的阅读缓存；未选择文件夹不因此从列表消失。
- 会话目录迁移在后台进行，持有该账号存储锁，创建完整目标后切换连接和会话设置。权限/磁盘错误不静默回退；不迁移用户外置 EML 导出目录。
- 备份暂存 SQLite 一致性副本，并固定引用的不可变对象；优先硬链接、跨卷复制。备份对象已压缩时不二次压缩。恢复仅接受允许的相对路径，不信任机器相关绝对目录。
- 网络沿用邮件会话的认证、代理、证书与交互/后台连接分工；禁止新建绕开配置的直连通道。
- 邮箱数据库操作持有短期 OS 文件锁，完整下载另持有每账号的任务锁；不同账号独立。锁文件保留，所有权由操作系统管理，进程崩溃释放。主要 IMAP 读取、同步与归档路径在阻塞任务中等待磁盘锁；目录迁移/快照占用超过 3 秒时返回可重试的忙提示。
- 迁移源目录留下 `<account>.redirect.json` 和小型锁文件，另一进程每次访问重新校验并关闭旧连接后打开目标。文件夹同步的低水位和完成标记不会被迟到的旧批次回退。目标已存在邮箱时拒绝覆盖。
- 若其它进程仍在下载此账号，保存存储设置会明确要求先暂停；任一实例的暂停会在约 250 ms 的轮询周期中关闭实际工作进程的套接字。清理持久化跳过标记，发布前在同一个跨进程锁下再检查，防止清理后重新出现。
- 同配置多实例可正常启动，待恢复备份的应用启动则要求其它使用该配置的实例先退出。恢复协调邮箱文件访问、删除旧重定向并更新连接代次，避免其它配置共享该邮箱的空闲连接继续访问被替换的旧文件。

## 已实现的存储与备份边界

- 每个会话仍有独立 SQLite；邮件原件为独立 `.eml.gz`，完整保留 MIME 字节（正文、内嵌图片、附件），SQLite 保存索引和引用。gzip level 3、128 KiB 缓冲、SHA-256 内容去重；单封读取、删除不重写整个邮箱。
- “仅这些/排除这些”只影响新原件下载；所有可选择文件夹仍同步摘要，既有原件继续保留。普通删除先进入 Trash；永久删除/服务器消失保留归档，可在 Local archive 离线阅读、导出 EML、保存附件。
- 显式清理暂停后台完整保存、删除选中引用及无其它引用的对象，记录跳过标记，避免下一次扫描自动下载回来。普通清缓存不删除完整归档。POP3 既有 `mail_local_raw` 仍作为本地邮箱权威副本，完整归档是额外压缩副本。
- 完整下载以 256 KiB 分段 BODY.PEEK 进行，恢复检查 UID/UIDVALIDITY/偏移/大小；完整 `.part` 也可恢复完成。任务由后端持有，关闭标签页不取消；暂停会关闭活动套接字并保留安全部分。失败显式重试。
- 完整存储没有 512 MiB 大小截断；内置阅读器/附件解码为防无限分配限制单封 512 MiB，更大的原件可流式导出 EML。
- 默认目录沿用应用 `mail-cache`；改目录迁移该账号索引、原件及附件缓存，失败回滚；备份不把机器上的绝对目录带到其它机器。
- 手动/自动/云端和本地目标均可选择邮件备份。SQLite 使用一致性快照，不可变原件用硬链接固定（跨卷复制），归档中的 `.eml.gz` 使用 ZIP_STORED；按需附件缓存一起收集。用户另存到任意目录的附件、EML 和草稿引用的外部文件不自动纳入。
- 备份 ZIP/恢复均流式处理；加密备份新写入 V2（1 MiB AES-GCM 帧和认证结束帧），仍可读 V1。旧版应用无法读取新 V2 加密备份。原件压缩文件本身未加密，备份可设置密码。

## 性能与并发

- 同步完整摘要索引与渲染分页分开，后台同步不再把数千封邮件全部加入可见 DOM；用户主动加载旧邮件保持原有深度。
- 列表行按稳定消息和线程属性缓存，日期格式器复用；正文预热进度最多每 250 ms 更新，批次主动让出主线程。已存完整原件跳过重复解压预热。
- 补充自动已读竞态回归：正文先于 STORE 返回时，原 effect 清理曾丢弃已成功的服务器已读结果，导致列表仍显示未读。挂载测试先复现失败再验证修复，成功结果始终更新对应 folder/UID；错误提示仍限于当前阅读上下文。后端同时记录正文/摘要 FETCH 的开始时间，拒绝用较早的服务器 flags 覆盖其后的本地 STORE 结果；较新的服务端状态仍可正常回写。
- 修复同步列表 ref 的竞争：旧渲染的 effect 曾将新的缓存列表覆盖为上一批；统一同步发布状态和 ref，最新邮件不会在安静轮询后从列表消失。
- 完整下载独立 IMAP 连接；解压/解析/导出在阻塞线程中，数据库锁仅定位并打开原件，打开的描述符保证清理/迁移期间读取一致。终端网络 I/O 不占用这些阻塞任务。
- 附件缓存读取先打开文件再释放数据库锁，后续复制使用流式临时文件；缓存写入先在锁外准备，锁内只发布。首次邮件 SQLite 打开和迁移初始化也移到阻塞任务，已初始化连接不重复执行整套表迁移。
- 原生大邮件测试服务另修复两处测试端复杂度问题：STORE 原来为每封邮件重新遍历求最大 UID，导致单次标记约 20 秒并占住服务共享锁；连续 UID 范围现在预先合并。保留失败响应和性能原始样本，不降低产品性能预算。
