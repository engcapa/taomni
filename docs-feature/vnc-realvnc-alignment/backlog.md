# VNC 客户端 RealVNC Viewer 对齐任务板

本板是 `docs-feature/vnc-realvnc-alignment` 批次的唯一任务来源，基于 [2026-09-30 RealVNC Viewer 7.15.1 实机参照](references/realvnc-live-audit-20260930.md)。卡片元数据只能由 `.agents/skills/vnc-realvnc-task/scripts/task_board.py` 写入。

```bash
tb="python .agents/skills/vnc-realvnc-task/scripts/task_board.py --doc docs-feature/vnc-realvnc-alignment/backlog.md"
$tb validate
$tb list --claimable
```

## 1. 规划规则

- 一张卡只处理一个可演示的用户结果，分别写清功能、交互、鼠标键盘、性能和保留行为。
- `deferred` 且 `p0.planning_required=true` 的卡需先完成 P1（DEC/AC/V、参照、测试合同）才能转 `ready`。
- 性能相关卡必须同时提交 `performance`（回放）与 `live-vnc`（真实服务器）证据，并给出 RealVNC 同场景数字（`realvnc-comparison`）；未测维度保持 `unverified`。
- browser 模式没有 VNC stub；连接后的 UI 由 jsdom 单测 + native 验证。
- 实测凭据只经环境变量 `TAOMNI_VNC_LIVE_HOST/PORT/PASSWORD` 传入；地址、口令、桌面名和屏幕像素不写入证据或提交。

## 2. 参照

RealVNC Viewer 7.15.1 (r18) Windows x64 独立版（Authenticode RealVNC Ltd，SHA-256 见参照 §1），第三方 RFB 3.7 服务器（安全类型 18+2，1680×1050）。Windows 11，125% DPI。

## 3. 建议领取顺序

PERF-001 → PERF-002 → INPUT-001 / INPUT-002 / VIEW-001 / SESS-001 / SESS-002 → PERF-003 → SESS-003 / CLIP-001 / CONN-001 → PERF-004 / INPUT-003 / VIEW-002 → QA-001。
