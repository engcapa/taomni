> 文档版本：v0.1（设计稿）
> 模型名：`replit-agent`（Replit Agent 为多模型产品，文件名使用产品名）
> 配套高保真原型：[`super-agents-proto-replit-agent.html`](./super-agents-proto-replit-agent.html)（单文件、无外部依赖，直接用浏览器打开）
> 前置设计：[`development-orchestrator-design.md`](./development-orchestrator-design.md)（统一开发配置、DAG 调度、worktree、成本策略、决策路由，本文沿用，不重复）

## 1. 目标与定位

把三类产品思路合并到本分支已有的多智能体编排上：

| 参照 | 取其所长 | 在本方案中的落点 |
| --- | --- | --- |
| Kiro Crew（规格驱动 + 多 agent 协作） | 需求 → 规格 → 任务图；规格是后续测试与评审的共同依据 | 规格图（Spec Graph）、验收标准 → E2E 追踪 |
| JetBrains ThinkRail（IDE 内的 agent 工作台） | 变更按 hunk 审阅、行内评论回传给 agent、可回退 | IDE-lite：变更视图、Keep / Revert / Ask、行锚评论、回执 |
| DeepSeek Super-agent（常驻路由、事件触发、异步、自带模型） | Router / Worker / Watchdog 分工，事件触发，长任务异步，BYOM | 编排内核，复用本分支已有的资源与角色配置 |

一句话定位：**用户只给目标与约束；系统自主完成"规划 → 实现 → 起环境 → E2E → 评审 → 交付草稿"，只在需要人决定的时候打断用户。**

### 1.1 设计原则

1. **少过程、多结论**：默认只呈现决策、重要信息、结果与阶段进展；代码改动流水和"思考中……"不进入主界面。
2. **证据先于完成**：任何"完成"都必须有可追溯证据（用例、trace、评审记录），没有证据不允许标记交付。
3. **不静默替换**：模型、环境、范围发生变化必须告知并可回改，沿用本分支"不静默替换模型"的约束。
4. **不自动合并**：终点是 PR 草稿，是否合并永远由人决定。
5. **复用现有配置**：LLM 供应商、coding harness、任务类型匹配、成本策略沿用统一开发配置，不再新增一套。

### 1.2 非目标

- 不重做统一开发配置、DAG 调度、worktree 管理（见前置设计）。
- 不做通用云 IDE；IDE-lite 只服务"审阅与定点修改"。
- 不在首期支持无人监督的自动合并与自动发布。

## 2. 总体架构

```
 事件源（用户 / Issue / CI / 定时）
        │
        ▼
 ┌───────────────┐   决策卡 / 阶段汇报 / 简报
 │ Router（常驻）│ ───────────────────────────► 用户界面
 │ 轻量模型      │ ◄─────────────────────────── 用户答复 / 修正
 └───────┬───────┘
         │ 任务模板 → 工作包 DAG
         ▼
 ┌─────────────────────────────────────────────┐
 │ Worker 池（每包独立 worktree + 独立上下文） │
 │ 规划 / 实现 / 测试生成 / 独立评审           │
 └───────┬─────────────────────────┬───────────┘
         │ 产物、证据               │ 心跳、进展信号
         ▼                          ▼
 ┌───────────────┐         ┌───────────────┐
 │ 质量门        │         │ Watchdog      │
 │ + E2E 环境    │         │ 轻量模型巡检  │
 └───────────────┘         └───────────────┘
```

### 2.1 三个常驻角色

| 角色 | 职责 | 明确不做 | 默认资源 |
| --- | --- | --- | --- |
| Router | 识别任务类型、选模板、拆工作包、汇总、发起决策、生成简报 | 不写代码、不跑测试 | 轻量 API 模型 |
| Worker | 在独立 worktree 中完成一个工作包并自测；规划、实现、测试生成、评审是不同 worker 角色 | 不跨包改文件、不直接联系用户 | 按任务类型路由（见 §7） |
| Watchdog | 判断 worker 有无实质进展、是否偏离目标、是否在重复读取同一批文件 | 不修改代码 | 轻量 API 模型 |

Watchdog 的处理顺序固定：先自行恢复（回到检查点、收窄搜索范围、重启 worker），恢复失败才升级为决策卡。用户看到的是"已自行恢复"的一条汇报，而不是过程。

### 2.2 事件触发：快路径与慢路径

| 事件 | 默认模式 | 快路径（秒级，不起 worker） | 慢路径（异步，起任务） |
| --- | --- | --- | --- |
| GitHub Issue 带 agent 标签 | 观察 | Router 分类并回复"已识别，是否处理" | 用户确认后按 bugfix / feature 模板建任务 |
| CI 主干失败 | 观察 | 摘要失败原因、关联最近提交 | 用户确认后建修复任务 |
| 定时（如每晚全量回归 E2E） | 关闭，可开启为自动 | 无 | 自动建"回归与稳定性"任务，仅产出报告 |
| 心跳（30 分钟无进展） | 自动 | Watchdog 判定 | 自行恢复或升级决策 |

触发模式分三档：**观察**（只记录和提示）、**受监督**（建任务但关键点问人）、**自主**（按推荐项继续，事后可改）。事件触发默认"观察"，用户逐条提升。

### 2.3 状态与持久化

- **规格图**：`spec/<mission>.SPEC.md` 保存验收标准（AC-n）、契约、范围；工作包与用例都引用 AC 编号。
- **检查点**：每个工作包完成、每次决策后落检查点，支持 Watchdog 回退和用户"更改决策"。
- **经验沉淀（Lessons）**：从评审与失败中提炼的仓库级约束（如"E2E 一律用 data-testid 定位"），用户可编辑、可删除、可停用，下次任务自动带入。
- **任务账本**：提示、决策、证据、成本，是简报与 PR 描述的唯一数据来源（§8.4）。

## 3. 任务模板与类型

Router 根据输入（需求文档、设计稿、Issue、日志、仓库规模）匹配模板；用户可在新建任务时手动指定。每个模板定义：阶段、默认人工决策点、产物、质量门、预算参考。

| 模板 | 适用输入 | 阶段 | 默认人工决策点 | E2E 策略 |
| --- | --- | --- | --- | --- |
| 0→1 · 有需求无设计 | PRD / 需求描述 | 澄清需求 → 方案设计 → 并行实现 → 质量验证 → 独立评审 → 交付 | 需求歧义、首版范围、界面方案、E2E 环境位置 | 自动生成，覆盖全部 AC |
| 0→1 · 需求与设计齐备 | PRD + 设计稿 | 设计核对 → 任务拆分 → 并行实现 → 质量验证 → 独立评审 → 交付 | 设计与需求不一致处 | 按设计稿生成 |
| 修复既有大库 Bug | Issue / 复现步骤 / 日志 | 复现 → 定位 → 修复 → 回归验证 → 独立评审 → 交付 | 修复范围（最小改动 vs 顺带清理） | 复现用例 + 受影响回归 |
| 既有库增量功能 | 需求 + 目标模块 | 调研 → 契约 → 并行实现 → 质量验证 → 独立评审 → 交付 | 契约变更、数据迁移 | 新增 + 回归 |
| 重构 / 批量迁移 | 迁移规则、范围 | 冻结行为 → 分片规划 → 分片执行 → 质量验证 → 独立评审 → 交付 | 分片边界、不兼容点 | 行为等价检查 |
| 补齐测试与 E2E | 现有模块 | 盘点 → 用例生成 → 稳定化 → 执行 → 独立评审 → 交付 | 无（默认全自动） | 核心产物 |
| 发布前验收评审 | 分支 / PR | 追踪覆盖 → 安全扫描 → E2E → 风险清单 → 结论 | 放行 / 阻塞 | 只执行，不改代码 |
| 事件触发 | Issue / CI | 观察 → 用户确认 → 转入上面某个模板 | 是否处理 | 随目标模板 |

### 3.1 各模板的关键差异

**0→1 无设计**：Router 先澄清（只问影响方案的问题，一次性给出带推荐项的选项），随后产出方案与界面线框，线框通过"与验收标准自动对照"后冻结，前后端据此并行；冻结后的契约变更必须走决策卡。

**0→1 有设计**：不重做设计，先做"设计—需求一致性"核对，把差异作为决策卡一次性列出。

**修复既有大库 Bug**：**先复现**。没有稳定复现用例不进入修复；修复遵循最小改动；影响面通过调用方分析确定，只对受影响范围跑回归，全量用例交 CI。大库场景下首要的成本控制是"读得少"：限定搜索范围，优先用本地小模型处理机械改动。

**补齐测试与 E2E**：不改业务代码；发现的缺陷以"已隔离用例 + 问题登记"形式呈现，而不是顺手修复。

### 3.2 自治级别

| 级别 | 行为 |
| --- | --- |
| 观察 | 只提示与汇总，不改任何东西 |
| 受监督（默认） | 关键点停下问人，其余自动 |
| 自主 | 所有决策卡按推荐项继续并记录，事后可回改；涉及交付、合并、成本超限仍然停下 |

决策卡的超时策略：无人响应超过设定时间（原型默认 30 分钟）后，按推荐项继续并记录"自动采用推荐项"，用户随时可"更改"，更改会让受影响的工作包回到检查点重做。

## 4. 质量体系

目标：**自动生成、覆盖完整、稳定、可自动执行**的 E2E，以及可审计的交付门。

### 4.1 验收标准 → E2E 追踪

- 每条 AC 至少对应一个 E2E 用例；一个用例可覆盖多条 AC。
- 追踪表是交付门之一：存在无用例的 AC，则"需求追踪覆盖"门不通过。
- 追踪表在界面的"质量"页中以 AC → 用例标签展示，点击用例可查看状态、trace、视频。

### 4.2 稳定 E2E 的生成规则

由测试生成角色强制遵守，评审角色检查：

1. 定位只用 `data-testid` 或可访问角色，不用文本或层级选择器；缺少 testid 时由 worker 在实现里补上。
2. 每个用例自备独立测试数据，用例之间无顺序依赖，可并行、可单独重跑。
3. 不使用固定 sleep；一律等待明确状态（网络空闲、元素状态、接口响应）。
4. 外部依赖用模拟服务或沙箱，不依赖真实第三方。
5. 失败时自动保留 trace、截图、视频与服务日志。
6. 交付前对每个用例**重复执行 5 次**（稳定性复跑）；任一次失败判定为偶发（flaky）。

### 4.3 失败分类与处置

| 分类 | 判定 | 处置 |
| --- | --- | --- |
| 稳定失败 | 重试仍失败 | 归因到代码或用例，限次自动修复（原型为 ≤2 次），仍失败则升级给用户 |
| 偶发 | 重试时通过 | 必须找出根因（竞态、等待、数据污染）并修复；允许"隔离"，隔离需记录原因、不计入通过数，并在交付说明中列为已知限制 |
| 环境失败 | 服务未就绪、端口占用 | 归环境层处理，不消耗用例修复额度 |

禁止通过"延长超时"掩盖偶发失败，该规则同时写入 Lessons。

### 4.4 交付门（必须全过）

| 门 | 内容 | 阻塞性 |
| --- | --- | --- |
| 类型 / Lint | 类型检查与静态检查 | 必须 |
| 单元 / 契约测试 | 受影响范围 | 必须 |
| 需求追踪覆盖 | 每条 AC 有对应用例 | 必须 |
| E2E 执行 | 用例全部通过；隔离项需说明 | 必须 |
| 稳定性复跑 | 复跑 ×5 全过 | 建议，交付前由系统自动触发；未做则交付按钮提示 |
| 独立评审 | 与实现者不同模型、不同上下文 | 必须 |
| 安全 / 依赖扫描 | 依赖审计、静态安全扫描 | 建议；高危阻塞 |

"必须"门未过时交付按钮禁用并显示原因；"建议"门未做时只提示。

### 4.5 独立评审

- 评审资源必须不同于实现资源（不同模型或不同 harness），上下文只含规格、diff、证据，不含实现者的推理过程。
- 发现分 high / medium / low；high 与 medium 必须处理或由用户显式接受，low 记入限制说明。
- 评审结论与处理结果进入质量证据包。

### 4.6 交付物

PR 草稿（不自动合并）+ 质量证据包：AC 追踪、E2E 结果与 trace 索引、评审记录、成本、已知限制、决策记录。

## 5. E2E 环境生命周期

要求：本地或云端均可**创建、部署、启动、健康检查、清理**，且由 Router 在合适时机自动编排，必要时才问用户位置。

### 5.1 执行位置

| 位置 | 适用 | 特点 |
| --- | --- | --- |
| 本地进程 | 轻量、无外部依赖 | 最快；隔离弱，依赖本机环境 |
| 本地容器（Docker / Podman） | 默认推荐 | 数据库与模拟服务隔离；首次拉镜像较慢 |
| 云端临时沙箱 | 本机资源不足、需并发 | 用完销毁，有额外成本；需上传代码，需用户确认 |
| 自带机器（轻量 daemon） | 公司内网、特殊硬件 | 代码与数据留在用户机器；与 BYOM 一致 |

选择依据：任务类型、预估资源、是否需要外部服务、成本策略与用户历史选择。位置作为一次决策卡出现，之后同仓库沿用。

### 5.2 环境清单 `.taomni/e2e-env.yaml`

仓库内声明式清单，由系统首次生成，用户可编辑并随代码评审：

```yaml
version: 1
mode: local-container          # local-process | local-container | cloud-sandbox | byo-machine
services:
  app:
    start: pnpm --filter web preview --port 5173
    health: { http: "http://127.0.0.1:5173/healthz", timeout_s: 60 }
  db:
    image: postgres:16
    seed: ./e2e/seed.sql
  payment-mock:
    start: pnpm --filter mock-payment start
    health: { http: "http://127.0.0.1:9090/ping" }
ports: [5173, 8080, 9090]
secrets:                        # 只引用 Vault 中的测试账号，不写明文
  E2E_USER: vault://e2e-user
teardown: always                # always | on-success | never
```

### 5.3 生命周期

1. **解析清单**：缺失则由 worker 生成并作为变更提交评审。
2. **预检**：端口占用、磁盘空间、浏览器驱动、容器运行时、测试账号密钥是否可用；任何一项不通过给出可操作提示，不继续。
3. **创建隔离环境**：独立网络、独立数据库、独立端口偏移，避免与开发服务冲突。
4. **安装依赖与种子数据**。
5. **构建并部署候选版本**：使用当前 worktree 的产物。
6. **启动服务并健康检查**：按清单逐服务等待 health；超时则收集日志并判定环境失败。
7. **运行 E2E**，失败用例保留证据。
8. **清理**：按 `teardown` 策略回收容器、进程、沙箱；云端沙箱必须有最大存活时间。

密钥只通过 Vault 引用，不进入日志、产物、简报或 PR 描述。

## 6. 低噪声输出模型

这是本方案区别于一般 agent 界面的核心。

### 6.1 主界面只出现四类内容

| 类型 | 说明 | 是否打断用户 |
| --- | --- | --- |
| 决策卡 | 需要人决定；选项数 ≤3，一项标"推荐"，每项给出成本与影响 | 是（进入"待我处理"） |
| 阶段汇报 | 每阶段完成给出结论、产物标签 | 否 |
| 里程碑 | 带数字的进展（工作包 X/Y、用例覆盖 n/m） | 否 |
| 结果 | 交付卡：覆盖、稳定性、评审、成本、已知限制 | 视通知设置 |

### 6.2 三档详略

| 档位 | 显示 | 用途 |
| --- | --- | --- |
| 仅需要我 | 决策卡与失败、阻塞 | 离开后回来快速处理 |
| 里程碑（默认） | 以上 + 阶段汇报 + 里程碑 | 日常 |
| 全部过程 | 展开被折叠的过程输出（带时间、角色、一句话） | 排查 |

被折叠的过程输出以"N 条过程已折叠 · 摘要"一行显示，用户主动展开才出现；即使在"全部过程"档，也只展示一句话事件，完整日志在"代码 → 终端"与证据包中。

### 6.3 进度表达

- 用**工作包 X/Y**与"进行中 / 等待你"计数，不使用无法兑现的百分比。
- 成本以用户自定义的"点数 pt"表示，并显示相对预算的比例。

### 6.4 简报按钮

任务头部的"简报"按钮根据**任务账本**即时生成，不调用模型、不产生费用：

1. **清晰简报**：你的提示 → 决策记录（含推荐项是否自动采用）→ 开发进度（工作包状态）→ 质量证据（门、用例、评审）→ 成本 → 待办。
2. **PR 描述草稿**：变更概述、AC 覆盖、测试证据、已知限制、评审结论。

支持"复制 Markdown"。简报的每个事实都能追溯到账本条目，避免模型转述造成偏差。

### 6.5 通知

按事件分级开关：需要决策、阻塞、里程碑、交付、预算 80%、Watchdog 介入。默认只开前四项。

## 7. LLM 供应商、Harness 与成本

沿用统一开发配置，不新增第二套。

### 7.1 资源与角色映射

- **资源**：API（OpenAI Chat / Anthropic Messages 等协议）、CLI harness（Claude Code stream-json、Codex app-server、opencode ACP 等）、本地模型，均由用户在统一开发配置中添加并检测可用性。
- **角色映射**：Router、规划/设计、实现、测试生成、独立评审、Watchdog 各自映射到一个资源，可按任务覆盖。
- **约束检查**：评审与实现使用同一资源时界面提示"评审与实现已异构"状态失效，并建议更换。

### 7.2 任务类型默认路由

| 任务类型 | 规划 / 设计 | 实现 | 测试生成 | 评审 |
| --- | --- | --- | --- | --- |
| 0→1 | 强推理 API（一次联合推理，少调用） | 跨文件强 harness | 与实现不同的 harness | 与实现不同 |
| 既有库 Bug | 轻量或不需要 | 小改动交本地模型或轻量 harness | 同左 | 与实现不同 |
| 补齐 E2E | 无 | 无 | 测试向 harness | 强推理，只读 |
| 事件触发 | Router 轻量模型 | 视转入模板 | 视转入模板 | 视转入模板 |

### 7.3 成本规则

1. 点数由用户在配置中定义（相对成本，不等同市场价）；预算按任务、按月两级。
2. **成本感知选择**（可开关）：在用户允许的候选集合内，按任务类型优先较便宜资源；不会选择用户未授权的资源。
3. 达到预算 80% 通知；超限默认**暂停并询问**，不静默继续。
4. **没有可用资源时停下并告知**，不静默替换为未授权模型。
5. 预估给出范围（如 80–160 pt）并随真实消耗修正；决策卡展示各选项的成本差。
6. 估算"预计省下 x%"仅在能说明依据时显示，标注为估算。

## 8. IDE-lite

目标：保留**审阅与定点修改**所需的 IDE 能力，其余交给任务视图。任务视图与代码视图在任务头部一键切换，状态共享。

### 8.1 代码视图构成

| 区域 | 内容 |
| --- | --- |
| 本次变更 | 文件树，仅显示变更文件，带 A / M / D 标记 |
| 编辑区 | 文件内容、变更 hunk 高亮、行号 |
| 底部 | 终端、E2E 输出、问题三个页签 |

### 8.2 变更审阅（ThinkRail 式）

- 每个 hunk 有三个动作：**保留**（标记已审）、**撤销**（还原该 hunk，并通知 worker 该意图被拒绝，避免被重新写回）、**询问 agent**。
- **行锚评论**：在任意行发起评论，评论以"带位置的指令"发给相关工作包；回复后以回执形式出现，评论位置随代码移动。
- 代码视图中有未处理决策时，顶部提示"请先回任务视图决策"，不让用户在两个视图中漏掉需要处理的事项。

### 8.3 边界

- 手工直接编辑当前被 worker 占用的文件会与 worker 冲突；首期代码视图对运行中工作包的文件默认只读，改动通过评论与 agent 协作，暂停任务后允许手工编辑。
- 不提供调试器、重构工具链、插件体系。

| 区域 | 内容 |

| 左栏：任务列表 | 顶部"待我处理"收件箱（跨任务聚合决策与阻塞），其下按仓库分组 |

### 9.1 原型可演示的场景

## 10. 分期

| 期 | 范围 | 退出标准 |
| --- | --- | --- |
| P0 | 任务账本 + 简报生成；决策卡数据结构与超时策略；低噪声事件模型（四类内容 + 三档详略） | 可在现有编排上回放历史任务并生成简报；过程输出可折叠 |
| P1 | 模板：0→1 无设计 / 有设计、Bug；规格图与 AC 追踪；交付门与"不自动合并"的交付卡 | 三个模板各完成一次真实任务并产出证据包 |
| P2 | E2E 环境清单与本地容器/本地进程生命周期；E2E 生成规则与稳定性复跑；失败分类 | 清单可复现环境启停；复跑 ×5 判定偶发 |
| P3 | 独立评审异构校验；安全扫描；Watchdog；事件触发（观察档） | Watchdog 恢复率与误报率有真实数据 |
| P4 | IDE-lite 变更审阅与行锚评论；云端沙箱与自带机器；自主档 | 手工审阅一轮不离开本产品 |

每期完成时再补充实测数据，**当前文档不含任何实测结果**。

## 11. 验收标准（设计级）

1. 同一个 0→1 任务，默认档下用户在主界面看到的条目不包含逐文件改动与"思考中"类文案。
2. 决策卡超时后按推荐项继续，且账本、简报、界面三处一致；"更改"能让受影响工作包回到检查点。
3. 任一 AC 缺少用例时，交付按钮禁用并指出缺哪条 AC。
4. 复跑 ×5 中任意用例出现失败，该用例被标记为偶发，不能计为通过，除非被隔离并写入限制说明。
5. 评审资源与实现资源相同时有明确提示，且评审门不显示"异构"。
6. 预算超限暂停并询问；没有可用授权资源时停下并告知，不换用未授权模型。
7. E2E 环境预检失败时给出可操作提示，且不开始部署；清理后无残留容器或进程。
8. 简报与 PR 描述中的每项事实可追溯到账本；密钥不出现在任何输出中。
9. 工作包文件被占用时，代码视图默认只读。

## 12. 风险与待决问题

| 风险 | 缓解 |
| --- | --- |
| 低噪声导致用户不信任 | 简报、证据包与"全部过程"档随时可查；每个"完成"附证据 |
| 推荐项自动采用造成方向偏移 | 仅受监督/自主档启用；涉及范围、契约、成本、交付的决策不自动采用；可回改并回到检查点 |
| E2E 稳定性规则增加生成成本 | 复跑 ×5 只在交付前触发；用例并行执行；失败时才保留重型证据 |
| 本地容器依赖用户机器 | 预检给出具体缺失项；允许降级为本地进程或云端沙箱（需用户确认） |
| 异构评审成本上升 | 评审只读规格与 diff；小改动使用轻量评审资源，仍须异构 |
| 大库上下文过大 | 限定搜索范围、分包独立上下文、Watchdog 检测重复读取 |

待决问题：

1. 决策卡的默认超时时长与"自主"档下可自动采用的决策范围，需结合真实使用确定。
2. 云端沙箱的计费口径是否纳入用户自定义点数，需与成本策略统一。
3. 行锚评论在 worker 大幅改写文件后的定位策略（按内容锚还是按行锚）需原型验证。
4. 经验沉淀的作用域（仓库级 / 用户级）与冲突处理规则。
