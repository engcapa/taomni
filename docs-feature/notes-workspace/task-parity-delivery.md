# Notes Workspace task parity delivery

Request: Notes space must offer the same priority, pinning, search, filters, task dates and other task controls as Tao Notes. Baseline: `748357249`. Branch: `feat/notes-workspace-task-parity`. Implementation and case commit: `df3e31ed7914afff31efd743adebd93be7e497f6`. Follow-up retry correctness commit: `68419057b6c23d90aa63e785d5190ceaf343c7df`. Native interaction/search correction: `fb857be7bbfc9984a96f797323be69664670f6b3`. Timestamp input/native context correction: `5b5c0f354876e74071f6979d72d3fd77996ce83c`. WebKitGTK overlay pointer-lane correction: `a3ed5be0322658c95015a8473a6b4776a9d2a36e`.

Implementation PR [788](https://github.com/engcapa/taomni/pull/788) was merged at `16c57970fb96e8da27eb695191cd41b7ee3f73d3`. The acceptance record continues to identify the tested implementation commit and exact source/case fingerprints.

The two editors now share task actions and properties: complete/reopen, pin/unpin, archive/restore, confirmed deletion, priority, due time, reminder, actual completion time, color, editable checklist and tags. Setting an actual completion time completes the task; clearing it reopens the task. Workspace properties collapse above the existing Markdown editor. Status/search changes only alter the sidebar list; open documents and dirty drafts remain mounted.

Workspace uses the same status menu, tag controls, card list and backend queries as Tao Notes. Status filters are OR-combined; tag and text searches are AND-combined. Search includes tag names, and ordering remains pinned first, then deadline, then recent updates. The independent workspace status preference is `notes.workspace.statusFilters`; creation resets nonmatching workspace queries. Existing Tao Notes preferences and database formats are preserved.

`notes_update_metadata` updates only provided task fields in a SQLite transaction. Omitted fields retain their values; explicit null clears nullable fields. This command never carries or overwrites title/body/source fields. Failed tag updates roll back the whole patch. Alert acknowledgements survive unrelated or identical updates; schedule/completion changes invalidate them. Per-note frontend task queues reject stale reads, retain failed operations for retry and refresh both Notes surfaces after checklist/task changes. Reserved `repeat_rule` data is preserved; recurring task execution is outside the existing UI's capability.
