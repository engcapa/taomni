### 0.2 要做什么

- **核心，不做插件**：89 项全部放核心，不新起插件、不等模块化 M0。main 上没有任何插件运行时（`plugin_invoke` 全仓 0 命中，`src-tauri/src/plugin/` 不存在，`module.json` / `modules.json` / `.taomni-plugin` 全仓无文件，见 §1.2），所以任何“放插件里”的说法在 main 上都是空的。taoffice 的 7 个插件仍等 M0，本设计不改变这一点。
- **主战场是通用查看器**：`ViewerShell` → `TextEditor` → `EditorSurface`（`src/components/viewer/`）今天只有保存 / 撤销 / 重做 / 查找 / 换行 / 字号 / 编码 / EOL，行操作、替换、书签、剪贴板历史、折叠、显示符号、文档地图全部空白；工作区 `CodeMirrorHost`（`src/components/editor/workspace/`）已有其中大部分。做法是**把工作区已有的命令下放到查看器，而不是在查看器里重写第二套**（§4）。
- **共享文本工具层**：新建 `src/lib/notepad/`（纯 TS，无 React）：文本变换（行操作、大小写、空白、去重、排序）、编码/EOL 工具、哈希/编解码、宏命令表、会话/备份模型。查看器与工作区都调它；CodeMirror 扩展只做“把命令接到编辑器上”那一层（§4.2）。
- **不换编辑器内核**：继续用 CodeMirror 6（`@codemirror/* ^6.x`，见 `package.json`），不用 Scintilla、不用 Monaco。Notepad++ 是 Scintilla 系的，Taomni 不是；用户决策里“Scintilla 编辑命令集（约 100 个）”已明确不支持，与此一致。

### 0.4 诚实预告：四处最容易产生误解的地方

1. **“支持”不等于“跟 Notepad++ 一模一样”。** Notepad++ 是 Windows-only、Scintilla、单进程桌面程序；Taomni 是 Tauri 2 + React 19 + Rust、跨 Windows/macOS/Linux。凡是 Windows 专有行为（UAC、回收站、cmd/PowerShell、文件关联、注册表）都要改写为跨平台口径，见 §5.1 与 §7。评审时按本设计的跨平台口径验收，不按“在 Windows 上跟 Notepad++ 逐项对齐”验收。
2. **大文件做不到 2 GB。** Notepad++ 64 位版已取消 2 GB 打开限制；Taomni 文本编辑上限今天是 5 MB 可编辑 / 20 MB 硬上限 / 256 KB 分段读（`src/lib/viewer.ts:4-6`）。本设计 P0 **不改这个上限**，只做 200 MB 阈值式的逐项降级口径（§8.2）；把上限抬到 50 MB 是 P1 的 spike S-N3，不是承诺。
3. **代码类“不支持”不等于 Taomni 没有代码能力。** 工作区已有语法高亮、折叠、LSP 补全、括号匹配、注释切换等全套能力（§1.1），用户决策只是“不把这些能力下放到通用文本查看器、不为 Notepad++ 另做一套”。工作区代码能力原样保留，不动。
4. **宏不是录按键，是录命令。** Notepad++ 宏录的是编辑操作；Taomni 宏录的是**已注册的文本命令**（§5.6 的可录命令表），弹窗类操作与语言选择不可录。`src/lib/i18n/locales/zh-CN.ts:949` 现在明文写着“本阶段尚未启用宏录制功能”，实现时这行文案要随功能一起改掉，不要留着。

### 0.5 成功标准（验收口径）

- AC-N01：89 项支持项在评审通过的版本里全部可用，43 项不支持项在界面上**不出现**（不是灰掉、不是占位页），待定项在评审前有明确结论。
- AC-N02：查看器与工作区同一份文本命令只实现一次（`src/lib/notepad/`），两处行为一致；回归用例覆盖“查看器里做的行操作与工作区里做的结果相同”。
- AC-N03：5 MB 以内文件全功能可用；5–20 MB 只读分块浏览 + 确认后编辑；超过 20 MB 拒绝编辑并明示原因与上限（§8.2）。
- AC-N04：远程文件沿用现状——只读临时副本，不回写；会话快照与备份只写本地应用数据目录，不写回远程（§6）。
- AC-N05：macOS 上标准动作为 Cmd 键（`Cmd+S` 保存、`Cmd+Z` 撤销等），`Cmd+,` 进设置、`Cmd+W` 关当前文档；Windows/Linux 用 Ctrl；快捷键可改键且冲突时有提示（§7，仓库 `AGENTS.md` macOS 一节）。

### 1.4 一条红线：不接受 sidecar（沿用 taoffice §1.4）

- 本设计不引入任何外部进程：不跑外部编辑器、外部 diff 工具、外部拼写检查服务、外部打印服务。哈希/编解码/ diff /打印全部用编进应用的 Rust/TS 库或系统打印对话框。
- 拼写检查已明确不支持，不因此引入 Hunspell sidecar 或云端拼写服务。

## 2. 目标、原则、非目标

### 2.1 目标

- 一个文本编辑入口：文件浏览器、终端链接、SFTP、Tao Agent、邮件附件点开 txt/log/ini/md 等纯文本文件，都进同一个查看器路由（`openFile`），89 项功能在查看器里可用；工作区代码文件继续走 CodeWorkspace，行为与查看器一致（同一份命令）。
- 核心默认带全部 89 项；不支持的 43 项不在界面上出现，不留灰掉的菜单、不留“即将推出”占位。
- 每个支持项有明确的落点（查看器 / 工作区 / 共享层 / Rust 层）、优先级（P0/P1/P2，沿用用户决策表的优先级）与验收标准（§9）。

### 2.2 原则

- **下放，不重写**：工作区已有的命令（行操作、查找替换、多光标、书签、剪贴板历史、快捷键自定义）下放到查看器；查看器缺的才新写，且新写进共享层，两条栈共用。
- **纯函数优先**：行操作、大小写、空白、去重、排序、编解码、哈希先写成纯 TS 函数（可单测、无编辑器依赖），再包一层 CodeMirror 命令；不要把变换逻辑写进 React 组件里。
- **查看先行，编辑分档**：P0 是文件生命周期 + 基础编辑 + 查找替换 + 视图基础；P1 是会话/备份/宏/工具箱/对比；P2 是双视图/文档地图/打印设置等打磨项（§9）。
- **离线优先**：全部 89 项本地完成，不调云端服务；远程文件只读，不回传（AC-N04）。
- **跨平台口径**：Windows 专有行为一律改写为三平台口径（§5.1、§7）；macOS 快捷键与菜单按仓库 `AGENTS.md` macOS 一节。
- **许可证先行**：新引的库先过合规评审；GPL/LGPL/AGPL 的库不进核心（与 taoffice 一致）。

### 2.3 非目标（本设计不做）

- 不做代码类 14 项（除可点击链接）：语法高亮（查看器只保留已有的 json/yaml/xml/svg/html/md 6 种语言动态加载，不扩展到约 90 种）、代码折叠、自动完成、函数列表、括号匹配、注释、缩进设置、语言菜单、UDL、Lexer 插件、智能高亮、代码片段、ErrorList/NFO。
- 不做插件体系：Plugins Admin、手动安装/导入插件与主题、插件 API、脚本插件（PythonScript/LuaScript）、NppExec、Run 菜单、第三方插件生态、NppFTP、NppExport。
- 不做 Windows 专有：监控模式（命令行 `-monitor`）、移至/克隆到新实例、始终置顶、在浏览器中查看、文件关联、多实例、命令行参数集、云同步配置、便携模式、更新检查（更新走 Taomni 自身的 `tauri-plugin-updater`，不在本设计内）。
- 不做拼写检查、按码位范围查找、文本方向独立命令、隐藏行、在项目中查找、文件夹工作区、项目面板、右键菜单定制、界面本地化。
- 不做 CAD/Office/PDF/视频等 taoffice 插件负责的类型；不做 OCR、云端协同编辑、移动端查看器。

## 3. 功能总览：按类别汇总（逐项表见 decisions 文件）

“Taomni 现状”一列的口径：已有 = main 上已实现且可直接复用；部分 = 只在一条栈上有，或只有底层无 UI；没有 = 两条栈都没有。优先级沿用用户决策表；“—”表示用户未给优先级，本设计在 §9 里补了分期。

| 类别 | 支持 | 不支持 | 待定 | Taomni 现状要点 |

## 4. 架构：共享层 + 两条栈

### 4.1 落点总图

```
用户打开 txt/log/ini/md 等纯文本
  └─ src/lib/openFile/index.ts openFile()（不变，分流逻辑不变）
       ├─ 工作区代码文件 → CodeWorkspace / CodeMirrorHost（已有，复用）
       └─ 散文件 / 查看器文本 → ViewerShell → TextEditor → EditorSurface
            └─ 新增：src/lib/notepad/（共享层，纯 TS + CodeMirror 扩展）
                 ├─ transforms/   行操作、大小写、空白、去重、排序、列编辑
                 ├─ search/       Mark、书签行操作、增量查找、令牌样式
                 ├─ session/      文档会话、最近文件、定期备份、保存时备份
                 ├─ macro/        宏录制/回放/存储/安全校验
                 ├─ tools/        字符面板、脱敏、哈希、MIME、Converter
                 ├─ compare/      文件对比（MergeView 内核，见 §5.7）
                 └─ print/        纯文本打印与打印设置
            └─ Rust 层（只补缺口）：编码扩展、备份目录 IO、系统回收站、打印走前端
```

- **不新增 `FileKind`**：文本功能不新增文件类型，`classifyFile.ts` 的 8 种分类不动；`supportsFileViewer` 的 5 种支持列表不动（pdf/source 仍走系统应用，不因本设计改变）。
- **不新增插件注册点**：本设计 89 项全部在核心里实现，不需要 taoffice §5.3 的“插件注册类型”扩展点；那个扩展点仍是 taoffice 的 P0，待 M0，不在本设计内提前做。
- **文件体积红线**：沿用仓库 `AGENTS.md`——手写文件 200–500 行为宜，超过 500 行拆分，新文件/模块不超过 800 行；`src/lib/notepad/` 按上图子目录拆，每个子目录一个责任，UI 壳只做组合与接线。提交前跑 `pnpm check:refactor` 与 `pnpm build`（两者都含 800 行检查）。

### 4.2 共享层 `src/lib/notepad/` 的分层

| 层 | 内容 | 依赖 |
|---|---|---|
| 纯函数层 | `transforms/*`：行排序（字典/忽略大小写/本地化/整数/小数逗号/小数点/行长，升/降序，稳定排序）、去重（全部/连续）、删空行（含仅空白字符行）、反转/随机打乱、合并/拆分行、插入空行、8 种大小写转换、Trim（行首/行尾/两端）、TAB↔空格（全部/仅行首）、行尾转空格 | 无编辑器依赖，可单测；输入是字符串/行数组，输出是新文本 + 选区映射 |
| 编辑器命令层 | 把纯函数包成 CodeMirror 命令：`notepadCommands.ts`，每条命令有 id、标题、默认快捷键、可录性（见 §5.6）；查看器与工作区共用同一份命令表 | `@codemirror/state/view/commands`，`src/lib/notepad/transforms/*` |
| 状态层 | 会话、最近文件、备份、宏、打印设置、文本偏好（换行、字号、显示符号、文档地图开关等） | 现有 store 模式：优先复用 `documentStore` / `viewerDrafts` / `local_history` 的存储模式，新增 store 时按 `src/stores/` 现有命名 |
| Rust 层 | 只补三处缺口：① 编码/字符集扩展（`encoding_rs` 已有，补 UI 覆盖）；② 备份目录 IO 与定期快照写盘；③ 系统回收站（跨平台，见 §5.1） | `src-tauri/src/viewer/*`、`src-tauri/src/backup/*` 的现有模式，不另起一套备份系统 |

- **查看器优先**：P0 的新命令先接进 `TextEditor` / `EditorSurface`；工作区已有的同名命令改调共享层（行为不变，只换实现），不要留两份排序/大小写实现。
- **Markdown 的特殊处理**：Markdown 文件走 `MarkdownEditor`（复用 `EditorSurface`），89 项里与 Markdown 冲突的（如行操作改动 Markdown 结构）不做特殊豁免——行操作就是纯文本行操作，用户在 Markdown 里用排序/去重时自行承担语义后果，界面不另做 Markdown 感知。

### 4.3 与 taoffice 的关系

- taoffice 核心已含 md/txt/html/代码文件/图片/压缩包；本设计是**taoffice 核心里“文本编辑”那一块的加深**，不是新插件、不是新文件类型。
- 本设计不改 taoffice v1.3 的插件清单（PDF/Word/Excel/PPT/Visio/Project/视频 7 个插件）与优先级；文件对比、打印等 89 项里的功能不因 taoffice 插件而重复实现——例如 Word 插件的块编辑与本设计的行操作是两回事，各做各的。
- 若将来 M0 落地，`src/lib/notepad/` 的命令表可作为插件宿主可调用的文本命令表复用，但本设计不为此预留插件接口，不提前写 `module.json`。

### 5.8 插件与扩展（1 支持 / 9 不支持）

- **唯一支持：文件对比 Compare / ComparePlus**（P1）：两个文件/选区/剪贴板内容并排 diff，可忽略空白/大小写。
  - **Diff 内核选型（评审点，见 §14.1(g)）**：推荐用 `@codemirror/merge` 的 `MergeView`（Git Diff 已在用，`src/components/git/DiffViewer.tsx`），**废弃**工作区自研逐行位置比对（`editorCompareModel.ts`，2 MB 上限，按行号位置比对，不是真正的 diff 算法）。统一后：任意两文件对比与 Git Diff 共用 MergeView，忽略空白/大小写选项由 MergeView 的配置实现；上限从 2 MB 提到 5 MB（与文本编辑上限对齐），超了提示“文件过大，请用外部 diff 工具”。
  - ComparePlus 的 Git/SVN diff 不做——Git diff 已有独立入口，不重复。
- 其余 9 项不做：Plugins Admin、手动安装/导入插件与主题、NppExport、NppFTP、脚本插件、NppExec、Run 菜单、插件 API、第三方插件生态。**特别说明**：文件对比在 Notepad++ 里是插件提供的，在 Taomni 里是核心功能，不因此新起插件体系。

## 6. 数据、存储与文件格式

| 数据 | 存储位置与格式 | 说明 |
|---|---|---|
| 文档会话 | 应用数据目录，JSON，扩展名 `.taomni-session.json`（待确认，§14.1(c)） | 内容见 §5.1；不含脏内容；加载时缺失文件跳过并提示 |
| 最近文件 | localStorage `taomni.recentFiles.v1`，上限 50 条 | 与最近工作区（`taomni.recentWorkspaces.v1`）分开；远程与邮件附件不进 |
| 定期备份与保存时备份 | 应用数据目录 `backup/notepad/`，原文件名 + 时间戳 + 哈希 | 每文件最近 10 份；磁盘配额超限时停备并提示；不写原目录，不污染用户文件夹 |
| 脏草稿 | 沿用 `viewerDrafts`（localStorage `taomni.viewer.drafts.v1`） | 重启后恢复并提示“磁盘文件未被改动”；定期备份写盘后，草稿仍保留直到保存或关闭 |
| 宏 | 应用数据目录 `macros.json` + SHA-256 校验哈希（另存） | 不用 `shortcuts.xml`；被外部修改时警告（§5.7） |
| 快捷键 | 沿用 `KeymapSchemeV3` 的存储 | 查看器命令纳入同一套方案；多套草案方案可保存 |
| 文本偏好 | 新建 `src/stores/notepadPreferences.ts`，localStorage | 收敛文本编辑偏好；老键一次性迁移 |
| 搜索历史 | 沿用 `searchPanel/history.ts`（`SEARCH_HISTORY_LIMIT`） | 查找/替换下拉框跨会话记忆 |
| 书签 | 文档级 store，随会话保存；不进磁盘文件 | 关闭文档后书签丢失（与 Notepad++ 会话保存书签的区别：Taomni 书签只在会话文件里保存，不写进原文件） |
| 打印设置 | 打印设置 store，localStorage | 行号、页边距、页眉/页脚、颜色映射 |

- **不引入新数据库表**：会话、备份、宏都用文件（JSON/纯文本备份），不新开 SQLite 表；本地历史表（`local_history.rs`）已有，可作为“恢复上一版本”的底层，但本设计不把它做成用户可见的版本历史功能（那是另一项功能）。
- **远程文件**：会话与备份只存本地路径；远程只读副本的路径不进会话（下次启动无法复开），不进备份（不回写远程）。

## 8. 大文件、编码与性能

### 8.1 编码

- Rust 层：`encoding_rs` 已有，补 ANSI 代码页与字符集的显式选择；检测沿用 64 KiB 采样（BOM → UTF-8 合法性 → UTF-16 零字节启发式）。
- 前端：编码下拉扩展到全量标签；转换保存时做字节级校验（字符数不变才保存，见 §5.1）。

### 8.2 大文件（P0 不改上限，P1 再议）

| 文件大小 | P0 行为（不变） | P1 目标（spike S-N3 后定） |
|---|---|---|
| ≤ 5 MB | 全功能可编辑 | 不变 |
| 5–20 MB | 只读分块浏览（256 KB 分块），确认后整档编辑 | 评估是否把可编辑上限抬到 50 MB（只读分块不变） |
| > 20 MB | 拒绝编辑，明示原因与上限 | 评估只读浏览上限（不承诺 2 GB） |
| > 200 MB（Notepad++ 高亮阈值） | 不适用（已超 20 MB 上限） | 若 P1 抬上限，超过 200 MB 时关闭语法高亮（查看器只有 6 种语言，影响小）、自动完成（查看器无）、快照备份、自动换行、智能高亮、文档地图，阈值可配（设置 → 性能） |

- **不承诺 2 GB**：2 GB 打开需要流式编辑器 + 虚拟化渲染，是另一个量级的重构，不在本设计内。
- 性能基线：5 MB 文件打开 < 1 秒（本地 SSD，评审时实测，不写死数字进验收——验收只测“5 MB 以内全功能可用”，见 AC-N03）。

## 10. 风险

| 风险 | 影响 | 缓解 |
|---|---|---|
| 两条栈行为分叉 | 查看器与工作区同一命令结果不一致 | 共享层唯一实现；回归用例覆盖“两处结果相同”（AC-N02） |
| 双视图共享缓冲区丢光标/选区/撤销历史 | P1 最难项延期 | spike S-N2 先行，不通过则双视图/克隆降级为“只读第二视图”（见 §11） |
| 文档地图性能 | 大文件卡顿 | spike S-N1；>200 MB 时关闭（§8.2） |
| 宏录制范围失控 | 录了弹窗操作导致回放失败 | 可录命令表白名单；不可录命令不进入宏 |
| 备份磁盘占用 | 定期备份 + 保存时备份写满磁盘 | 每文件 10 份保留 + 磁盘配额提示（§5.1） |
| macOS 快捷键冲突 | F11/F12、`Cmd+W` 等与系统冲突 | §7.2 已标注；评审时逐项确认；可改键 |
| 编码转换不可逆丢失 | 字符丢失后无法恢复 | 转换前校验字符数，丢失时警告并列出数量（§5.1） |
| 会话文件格式选错 | 将来改格式要迁移 | JSON 格式带 `version` 字段；加载时按版本迁移 |
| 与 taoffice/M0 的边界混淆 | 把插件功能误放进核心 | §4.3 写明边界；评审时按“89 项全部在核心”检查 |
