# Taomni 整体 UI 布局与易用性重构设计

> 版本：v1 · 2026-10-02。状态：**推荐方案设计稿，待体验反馈**。本轮交付一份设计文档和一个独立 HTML 原型，不拆分开发任务、不修改产品代码。
>
> 代码基线：`da369bca`，调研时工作区干净。适用产品：Windows、macOS、Linux 的 Tauri 桌面应用。现状依据为源码；本轮未实测当前产品的桌面 UI。原型验证只能证明原型自身的布局和交互。
>
> [打开交互 demo](ui-layout-usability/demo.html)：保存后用浏览器直接打开，无需网络、依赖安装或启动 Taomni。上方可切换开发、运维双栏、邮件、多 Tab 总览、首页，并切换宽度、平台示意及浅/深色。

## 1. 推荐结论

建议把 Taomni 组织成**稳定的工作区域 + 统一的会话工具面板 + Tao 助手**。最上方明确区分窗口操作、全局入口与内容 Tab；左侧提供固定首页入口和当前内容工具；中间承载完整的工作内容；Tao 默认收起，需要时从右侧打开。

文件、Git、数据库对象树属于当前工作内容的工具。聊天、便签、通知属于跨工作内容的辅助能力。它们可以共用一套停靠、收起、焦点和尺寸规则，但保留清楚的归属。完整邮件客户端、数据库客户端、Code Workspace、远程桌面继续作为中间的内容 Tab。

针对本次五项关注，推荐如下：

| 关注点 | 推荐行为 | 用户得到的改善 |
|---|---|---|
| 全局布局与面板是否合并 | 会话导航、项目、SFTP 附属文件、Git 工具复用左侧面板位置；Tao 放聊天、便签、通知；底部承载当前工作区的运行输出 | 同一条左侧工具栏，同一套开关规则；主要内容保留足够空间 |
| 多 Tab 如何快速切换 | 保留单行 Tab，增加有明确名称的“总览”；总览使用大内容预览卡片、搜索、工作组和类型筛选 | 内容很多时能看到自己要找的工作，而不仅是被截断的标题 |
| 不同类型如何切分 | 按工作关联组织 Tab，按类型筛选；支持用户选择两个已有内容左右或上下并排 | SSH 与数据库、代码与 Git、邮件与终端可以围绕同一件工作摆放 |
| 标题按钮怎么清晰 | 标题栏采用“总览 / 视图 / 新建 / Tao”的图标加文字；当前内容操作下移到内容工具栏 | 全局操作与当前会话操作的位置和名称都更明确 |
| Welcome 如何定位 | 面向用户命名为“首页”，固定在左侧工具栏最上方，始终可回到；保留内部 `welcome` 身份 | 不用在很多 Tab 中寻找 Welcome，回首页也不打断现有工作 |

本方案优先减少默认可见的复杂度。首次连接终端时，文件面板和 Tao 都收起；打开项目时显示项目树；打开数据库时显示对象树；打开邮箱时显示邮件文件夹。用户手动打开的工具在相同内容下记忆。高级停靠和独立窗口能力保留，通过面板菜单或“视图”发现。

## 3. 桌面软件参照与取舍

以下参照来自 2026-10-02 可访问的官方说明，未开展对应软件的现场对比或像素级测量。

| 参照 | 可借鉴的机制 | Taomni 的采用方式 |
|---|---|---|
| [VS Code · Custom Layout](https://code.visualstudio.com/docs/configure/custom-layout) | 主/副侧栏、Panel、编辑器分组；工具与编辑主体有稳定区域 | 左侧上下文工具、右侧助手、底部输出；简洁默认布局，保留进一步调整 |
| [IntelliJ IDEA · Tool windows](https://www.jetbrains.com/help/idea/tool-windows.html) | 工具窗口依附主窗口边缘，可重排或脱离至独立窗口 | 单一工具栏、清晰的工具窗口归属；Git/运行等复杂任务可独立展开；沿用当前工作区高级布局 |
| [macOS · Mission Control](https://support.apple.com/guide/mac-help/view-open-windows-spaces-mission-control-mh35798/mac) | 在集中视图中识别打开的内容，再选择返回目标窗口 | 大预览总览，用户主动进入；关闭总览原样返回，不自动重排正在工作的页面 |

整体组织的候选方案：

| 方案 | 体验优势 | 主要代价 | 建议 |
|---|---|---|---|
| A：统一会话工具位置，Tao 承载助手能力 | 工具与对象关系清楚；能同时查看文件和聊天；现有工作区能力可延续 | 需要区域协调，窄窗口必须有明确退让规则 | **推荐，demo 的主方案** |
| B：文件、Git、聊天、便签、通知全部放入 Tao | 入口少，所有侧面板都可从一个位置发现 | Tao 内部分类增多；文件与聊天要互相切换；Git 与项目上下文容易变成隐含状态 | 适合将 Tao 明确定义为所有工具的容器时采用；本稿不建议作为默认 |
| C：面板主要以浮层出现 | 中间内容不被持续挤压 | 容易遮住输入和结果；多个浮层的位置、关闭与焦点需要更多管理 | 用于临时查看和窄窗口，作为显式可选方式 |

A 同样统一面板基础规则，避免每个功能另造一种面板。合并的是宿主、入口规则和操作习惯；对象工具与助手的信息结构分别保持清晰。

## 4. 信息架构与区域分工

### 4.1 建议布局

```text
┌─────────────────────────────────────────────────────────────────────────┐
│ 窗口标题：Taomni ▾    查找内容或操作    总览  视图  新建  Tao    窗口控制 │
├──────┬─────────────────┬─────────────────────────────────────┬───────────┤
│ 首页 │ 左侧统一面板    │ 全局内容 Tab                         │ Tao       │
│ 会话 │                 ├─────────────────────────────────────┤ 可收起    │
│ ──── │ 一次一个视图：  │ 当前内容工具栏 / 两栏标题            │           │
│ 项目 │ 会话导航        │                                     │ 聊天      │
│ 文件 │ 项目 / 文件     │ 完整工作内容                        │ 便签      │
│ Git  │ Git 更改        │ 可左右 / 上下并排不同类型            │ 通知      │
│ 对象 │ 数据库对象      │                                     │           │
│ …    │ 邮件文件夹      │ 工作区内部文件 Tab 和编辑器分组      │           │
│      │                 │ 继续在 Code Workspace 内部          │           │
│ 工具 │                 ├─────────────────────────────────────┤           │
│ 设置 │                 │ 底部：当前内容的运行 / 终端 / 问题   │           │
├──────┴─────────────────┴─────────────────────────────────────┴───────────┤
│ 状态栏：当前内容状态、连接 / 任务反馈                   后台活动摘要     │
└─────────────────────────────────────────────────────────────────────────┘
```

图中枚举的是可能出现的区域，并非要求全部同时打开。左侧工具栏仅展示当前内容适用的常用工具，工具名不依赖悬停；首页、会话、工具、设置是稳定的全局位置。其余能力由“工具”目录和全局查找发现，避免把所有协议与功能都做成常驻图标。

### 4.2 各能力放在哪里

| 能力 | 默认位置 | 需要更大空间时 | 与 Tao 的关系 |
|---|---|---|---|
| 保存会话与目录 | 左侧“会话”视图 | 搜索 / 首页最近记录 | Tao 可引用用户主动提供的对象；不管理会话树 |
| SSH 附属 SFTP | 左侧“文件”，明确标注主机和路径 | 打开独立 SFTP Tab 或沿用独立窗口 | 聊天可引用选中的文件信息，不承载文件浏览器 |
| 本地文件 / 对象存储 | 完整文件 Tab；适用时提供左侧目录导航 | 与终端/编辑器并排 | 通知可显示传输结果并跳回来源 |
| Git | 左侧显示当前仓库的更改摘要 | 完整 Git Tab：历史、比较、多仓库、提交等 | Tao 可讨论差异；提交与仓库选择继续在 Git 中完成 |
| Code Workspace | 全局 Tab 内的完整工作区 | 全局与其他内容并排；内部仍可分编辑器组 | Tao 跟随被聚焦的工作区和文件上下文 |
| 数据库 / Redis / HBase | 完整内容 Tab；数据库对象导航属于对应内容 | 查询、结果等由客户端内部管理；全局可与终端并排 | Tao 辅助讨论查询和结果，实际执行仍在客户端内 |
| 邮件 / 统一邮箱 | 完整邮件 Tab；文件夹、列表、阅读区分工 | 阅读区最大化，必要时独立窗口 | 通知显示新邮件摘要，“打开邮件”回原账号和邮件 |
| LAN Chat | 完整 LAN Chat Tab，保留现有边缘停靠方式 | 当前已支持的独立/边缘入口 | 保留与 AI 聊天的不同身份；未读摘要可统一提示 |
| Tao 聊天 / 便签 / 通知 | 右侧同一助手面板的三个清晰页签 | 固定、临时浮层；高级菜单延续四边停靠及已有便签浮动能力 | 同一份内容状态，切换呈现方式不复制消息或便签 |
| RDP / VNC | 完整远程桌面 Tab | 独立窗口 / 全屏；支持条件满足后可并排 | 通知可回来源；不在 Tao 内嵌远程桌面 |
| 网络工具 / 代理 / MFA / 设置 | 各自的内容页面，从工具目录或应用菜单进入 | 沿用适合该工具的完整页面 | 只汇总适用的提示；MFA 和认证表单不进入内容预览 |

Git 工具按仓库能力呈现：本地终端和工作区可连接已确定的仓库；远端 SSH 只有实际声明支持时才显示对应 Git 功能，不能根据主机名称猜测仓库。本次不扩展远端 Git 后端能力。

### 4.3 面板打开、关闭与上下文

- 点击当前已展开的左侧工具，再次点击会收起；点击另一工具，在同一位置替换。面板标题显示对象名称、主机/仓库/路径，避免操作错对象。
- 切换到另一 Tab 或聚焦另一分屏时，左侧工具使用目标内容上次选择的工具；不适用的工具不渲染，也不沿用前一个 SSH 的文件连接。
- 打开“会话”是临时导航。选择目标后恢复目标内容的工具偏好；仅浏览会话树不替换中心内容。
- 收起面板、切换工具、回首页、进入总览或专注模式只改变呈现。正在进行的传输、查询、AI 输出和运行任务继续按原业务生命周期处理。
- 提交、上传、发送消息等动作在触发时绑定明确的对象 ID。动作期间焦点改变，不将未完成的操作重新绑定到新对象；异步响应只更新原对象状态。
- Tao 聊天默认跟随焦点。用户可以锁定聊天上下文，持续讨论原对象；锁定时持续显示名称和“恢复跟随”。锁定对象关闭后保留线程，显示“原内容已关闭 / 选择新的上下文”，不静默把正在进行的线程改绑。
- 打开通知来源时：优先定位已打开内容和对应内部对象；来源已关闭时提供“重新打开”，并显示连接/账号不可用的具体原因。

原型中的“上下文锁定”只模拟对象名称和消息归属；关闭被锁对象后简化为恢复跟随并提示。产品必须采用上述线程保留与显式重新绑定规则。

## 5. 尺寸、密度与空间退让

所有尺寸为逻辑像素设计起点，不是已测量的最佳值；实际产品还需在缩放、字体和本地化下验证。

| 区域 | 建议起点 | 规则 |
|---|---|---|
| 窗口标题 | 44 高；触发目标至少 30×30 | 与 Tab 行分开。真实窗口关闭按钮采用平台习惯的点击区域 |
| 左侧工具栏 | 56 宽；工具目标约 44×48 | 图标 + 简短名称；高级用户可选择图标模式，首次使用显示名称 |
| 左侧面板 | 默认 232；可拖动，常用范围 190–360 | 主内容不足时使用临时面板，不让持久宽度无限增长 |
| 内容 Tab 行 | 38 高；Tab 常用宽度 125–185 | 单行滚动，当前项自动显露；不无限缩小标题 |
| Tao | 默认 324；建议可调整 300–440 | 初始收起；临时查看使用右侧浮层，手动固定后占据一列 |
| 当前内容操作 | 36–40 高，按能力决定是否需要 | 连接、运行、截图、广播等靠近实际对象 |
| 底部工具 | 初次显示约 160–220 高，支持拖动 | 无任务时收起；不把输出复制到全局 Tab |
| 状态栏 | 22–24 高 | 只显示当前状态和可行动的后台摘要 |
| 文本 | 正文/主要控件 13–14；次要元数据 11–12 | 用户字体设置和缩放继续有效，不以缩小字体解决拥挤 |

空间按实际剩余工作区计算，不能只依据窗口总宽度。单个内容应声明可用的最小宽/高；两个内容并排的最小宽度是两者之和加分隔条。原型用 520 的单页基准、640 的邮件基准、760 的双栏基准演示退让；产品应使用各模块的实测能力声明。

建议的退让顺序：

1. 压缩全局查找展示为图标，保留“总览 / 视图 / 新建 / Tao”的可读名称。
2. 把会话导航或上下文左面板临时覆盖打开，保留用户的停靠偏好；关闭后工作区恢复。
3. 固定 Tao 使内容低于最小尺寸时，暂时使用浮层，明确显示“固定 · 空间不足”。放大后按偏好恢复，窗口缩放本身不改写偏好。
4. 同一窄窗口一次只显示一个临时侧面板：用户最后打开的左面板或 Tao 获得前景，另一面板暂藏，保留其数据和偏好。避免两侧浮层同时遮住大部分工作区。
5. 左右并排已低于内容最小宽度，而上下空间足够时，临时改为上下排列；放大后恢复所选方向。高宽都不足时提示“空间不足”，提供单页切换或独立窗口，不自动关闭内容。
6. 底部工具过高时减少占用；达到最小高度后提供最大化工具/单页查看。远程桌面使用既有缩放规则，不挤压原生输入映射。

“专注模式”暂藏工具面板、Tao 和底部输出，保留 Tab、标题栏和明确的“退出专注”入口。退出恢复进入前的布局。它不等于远程桌面全屏，也不关闭后台任务。

原型最低窗口示意宽度为 760；浏览器窄于此值时，外层演示画布可横向滚动。这个行为是演示边界，不是移动端产品设计。

## 6. Tab 组织与不同类型的切分

### 6.1 内容身份与组织轴

**全局 Tab 表示正在工作的对象；工作组表示它们属于哪件事；类型帮助识别和筛选。**

例如“发布准备”工作组可同时包含 taomni 项目、prod-api-01 SSH、production 数据库和仓库 Git。用户不必先到终端区执行一件事，再到数据库区继续同一件事。

默认继续按打开顺序摆放，支持拖动排序和固定常用内容。总览默认按已有保存目录组织；本地项目和临时内容可手动归入一个视图工作组。工作组只是视图元数据，不改写保存会话的 `group_path`、项目路径或账号配置，也不新建一套业务工作空间。

工作组命名与成员调整从总览中的组操作进入。会话源目录重命名后更新其默认组显示；手动视图归组保持用户选择。两个同名组用来源路径区分。新打开内容不会擅自移动现有 Tab；排序只因用户动作改变。

| 类型范围 | 全局 Tab 代表什么 | 内部仍保留什么 | 建议并排示例 |
|---|---|---|---|
| `terminal` | 一个本地 / SSH / 命令终端实例 | 滚动、输入、选择、终端工具、连接身份 | SSH + SSH；SSH + 数据库 |
| `sftp` / `file-browser` / `object-storage` | 一个完整文件工作上下文 | 路径、列表、传输、连接与目录导航 | SFTP + 终端；文件 + 代码 |
| `database` / `redis` / `hbase-shell` | 一个客户端连接或 shell | 查询文件、结果、对象浏览等模块内部结构 | 数据客户端 + 运维终端 |
| `code-workspace` | 一个工作区实例 | 内部文件 Tab、编辑分组、项目树、运行/调试/问题 | 工作区 + Git；工作区 + 文档/邮件 |
| `git` | 一个仓库或多根工作区的 Git 上下文 | 历史、变更、差异、多仓库选择 | Git + 代码 / 终端 |
| `mail` / `mail-unified` | 一个账号或统一邮箱页面 | 文件夹、列表、阅读、撰写、附件和账号选择 | 邮件 + 终端；代码 + 邮件 |
| `rdp` / `vnc` | 一个远程桌面实例 | 远端输入、缩放、连接与全屏 | 远程桌面 + 本地工具，受原生能力约束 |
| `lan-chat` | 一个 LAN Chat 页面 | 联系人、会话与文件传输 | 聊天 + 工作内容 |
| `nettools` / `sockscap` / `proxy-test` / `mfa` / `settings` / `placeholder` | 对应工具或状态页面 | 各自完整流程 | 按能力声明提供并排；认证交互不进入预览 |
| `welcome` | 固定首页 | 最近记录、恢复和启动入口 | 作为窗口级首页，不成为可并排对象 |

### 6.2 单行 Tab 与溢出

- 活动 Tab 用背景和下沿标记，同时保留类型图标。未保存、未读、新输出是独立状态，不能只靠一个相同颜色的小点区分。
- 鼠标滚轮/触控板可横向浏览，溢出时两端有可点击箭头和被裁切提示；当前项切换后自动显露。
- 右端固定显示“总览 + 总数”，标题栏也提供全局“总览”。Tab 行的计数是进入同一总览的近邻快捷入口，不是第二套列表。
- 首选把类型/工作组筛选放在总览内。若用户显式把筛选应用到 Tab 行，显示“显示 4 / 共 18 · 清除”，当前聚焦内容保留在行中并标注“筛选外当前项”；筛选不自动切换连接。
- 类型、工作组、标题搜索互相独立；清除筛选显示所有内容，隐藏不等于关闭。旧 `…` 的按目录、多选分组与查询发现能力应迁入总览，不能只保留一个简化类型下拉。
- 关闭当前内容后，在相同可见分组选择最近访问的未关闭内容；没有候选时回首页。批量关闭先汇总未保存/执行中风险，再执行原有关闭协议，不用隐藏面板的无确认行为替代。

### 6.3 混合内容分屏

全局“视图”提供“单页 / 左右并排 / 上下并排”，并排前选择另一个已打开内容。菜单显示标题、类型、对象和当前所在位置；也可从 Tab 菜单或拖到内容区的方向落点进入。同一对象在一个窗口内只占一个全局内容位置；进入并排是移动呈现，不是复制连接。

两个面板各有对象标题和当前焦点标记；点击内容或面板标题可聚焦。切换全局 Tab 时：目标已经在另一栏就聚焦那一栏，目标尚未展示就替换当前聚焦栏中的内容。被替换的内容仍在全局 Tab 和总览中可找回。

“合为单页”保留当前焦点内容，另一个返回仅打开状态。点击 Tab 的关闭按钮才关闭业务内容；面板的收起或退出分屏不关闭连接。布局调整不得触发重新连接、重新查询或重新加载整个工作区。

Code Workspace 的内部文件分屏保持独立：例如全局左栏是工作区、右栏是数据库，左栏内部仍可使用已有编辑器分组。尺寸不足时说明受限制的是哪一层，并提供最大化当前工作区。

现有终端多会话网格作为“终端网格”专门模式保留，入口移至终端布局/高级视图。已有网格布局、比例、广播选择和输入锁语义继续有效。混合两栏只改变呈现，**不会自动开启广播**；广播只向显式选中的终端发送，并持续显示目标列表和锁定状态。

初始建议对已有可重排内容支持两栏；每种类型都需声明原生适配条件。尤其 RDP/VNC、正在撰写的邮件、工作区编辑器不得用 HTML 原型中的模拟分屏作为已支持的证据。某种原生内容暂不支持并排时，菜单显示具体原因并保留独立窗口操作，不能点击后静默失败。

## 7. 大内容预览与快速切换

### 7.1 总览

“总览”在用户主动点击时覆盖工作区域；底层工作不重排。宽屏采用三列，较窄窗口两列，卡片建议宽 280–360、预览高 140–200。每张卡片展示：标题、类型、对象摘要、主体预览、连接/未读/任务状态、当前/另一栏标记。

总览包含一个搜索框，工作组 / 类型 / 最近使用三种组织方式，以及全部、代码、终端、数据、邮件等类型筛选。列表视图保留为可选高密度方式，供大量内容或关闭内容预览时使用。

搜索和筛选只改变总览结果，不切换工作页。点击卡片或 Enter 才确认切换；Escape 和关闭按钮回到原布局和原焦点。无结果明确显示“没有匹配的内容”，提供清除搜索，不自动关闭或重新连接任何会话。

方向键在卡片之间移动，Tab 可走到搜索、筛选、组操作和卡片。关闭卡片应使用独立控件，避免点击预览内容时误关。支持在总览里重命名、固定、归组和移到另一栏，沿用内容生命周期检查。

### 7.2 小范围快速切换

连续切换少数最近内容时使用轻量 MRU 列表：先显示最近访问的约 6–8 项，含标题、类型与对象；可选中等大小预览。完整总览仍由按钮进入，不把每次切换都变成大型卡片墙。

快捷键路由沿用 [shellShortcutRouter.ts](../src/components/editor/workspace/shellShortcutRouter.ts) 的 modal → active-workspace → active-tab → shell 优先级。工作区的内部文件切换不能被全局内容切换覆盖；按键与局部操作冲突时由显式路由决定归属。

原型采用 Ctrl/⌘+Shift+H 进入总览、Ctrl/⌘+Shift+K 查找、Alt+Home 回首页、F10 专注，仅用于浏览器演示。产品建议用现有详情入口的 Ctrl/⌘+Shift+H 扩展为总览，详情信息完整保留在卡片；其余候选键位实施前须核对工作区、邮件、终端、系统菜单和输入法冲突。F10 不直接作为产品全局默认，以免覆盖桌面菜单习惯；所有操作均有可点击入口。

### 7.3 预览数据与成本

| 内容 | 主体预览建议 | 回退 |
|---|---|---|
| 终端 | 最近一次可见屏幕的裁剪快照或有限行输出摘要 | 标题、主机、当前路径、运行状态 |
| 工作区 / 编辑器 | 当前文件的局部内容、文件名和修改状态 | 项目与当前文件摘要 |
| 数据库 | 当前查询片段和结果网格的有限行摘要 | 连接、数据库、当前查询标题 |
| Git | 当前差异或提交摘要 | 仓库、分支、更改数 |
| 邮件 | 默认主题、发件人和日期；启用正文预览时再展示有限正文 | 账号与未读数，不自动加载远程图片 |
| 文件 / 对象存储 | 当前路径和有限列表、传输状态 | 连接与路径 |
| RDP / VNC | 用户允许时复用最近可见帧；不为总览额外启动捕获或连接 | 主机、协议、连接状态 |
| MFA、认证、密钥表单 | 只显示元数据卡片 | 不显示验证码、口令或认证正文 |

预览以内容适配器提供的有限摘要/缓存为主，不能依靠复制业务组件、克隆 canvas/PTY 或创建很多隐藏 WebView 来生成。收集只在内容实际可见时进行；总览使用带时间的最近预览，有过期状态可辨认。没有摘要能力就显示元数据卡片，不能卡住整个总览。

内容预览可以全局关闭，也可按内容关闭。图像仅驻留内存，内容关闭或锁定应用后释放，不随布局写入磁盘。卡片列表虚拟化并按可见范围读缓存；缓存使用大小上限和 LRU 淘汰，后台不进行高频截图。具体缓存字节预算与首屏目标在实现前用 10 / 30 / 100 内容基线测量后确定，本稿不虚构性能结果。

原型中的所有预览来自内联模拟数据，包括邮件正文和远程桌面示意；没有读真实消息、采集屏幕或连接外部系统。

## 8. 窗口标题与按钮清晰化

| 位置 / 名称 | 点击行为 | 原有能力迁移 |
|---|---|---|
| Taomni + 菜单提示 | 应用菜单：设置、主题、语言、导入/导出、工具、帮助、退出 | 统一主菜单保留；macOS 与原生全局菜单保持同一命令来源 |
| 查找内容或操作 | 全局查找已打开内容、保存会话、项目、工具和命令；结果标注“切换 / 打开 / 操作” | 可复用现有命令注册，不能用模糊搜索替代主要可见入口 |
| 总览 + 数量 | 大预览 / 列表，搜索、分组和切换 | 迁入 `…` 的内容发现能力，以及详情面板的对象摘要 |
| 视图 | 单页、左右、上下、会话导航、专注、恢复布局；高级入口含终端网格及面板位置 | 接替无文字的分屏按钮，并明确分屏对象和恢复方式 |
| 新建 + 下拉提示 | 本地终端、已有/新会话、项目、数据库、邮箱及其他工具 | 保留当前新建菜单支持的 shell 选择等能力；新建会话配置和连接已有会话分别命名 |
| Tao + 状态 | 打开上次使用的聊天/便签页，通知 badge 表示未处理数量 | 取代不固定位置的默认悬浮入口；用户已有四边 ribbon 偏好仍可选择 |
| 内容标题 / 操作栏 | 重连、SFTP、Git、运行、截图/录制、脱离、终端广播等，按当前类型呈现 | 从窗口级操作插槽下移，捕获中与广播中仍持续显示状态 |
| 系统窗口控制 | 最小化、最大化/还原、关闭窗口 | 与关闭当前 Tab 明确分离，沿用实际 Tauri 窗口 API |

清晰原则：图标必须与名称、tooltip、可访问名称和状态一致。“视图”解释布局，“工具”解释功能目录；`…` 只用于当前对象的次要操作。打开型按钮显示展开状态，模式型按钮显示选中状态，禁用按钮给出原因。

Windows/Linux 在右侧使用应用现有窗口控件；macOS 左侧预留原生交通灯区域，复用当前 76 宽起点并在各缩放下实测，不重复绘制第二套窗口控件。标题栏保留独立空白拖动区域，按钮、搜索、Tab 拖动与系统拖窗区域互不覆盖；双击空白沿用最大化/还原。

窗口关闭走窗口级检查，Tab 关闭走内容级检查。快捷键、键盘菜单、PTT、语言、主题、捕获和更新提示都要有可发现的迁移入口，不能因简化标题栏删除功能。PTT 实际能力入口移入 Tao 聊天；持续录音/转录时在全局状态区保留明显的停止入口。

## 9. 首页 / Welcome

用户侧统一叫“首页”，内部继续使用 `welcome`，保留不可关闭语义和当前恢复链路。首页不占业务 Tab 数量、不随工作组/类型筛选隐藏，所有打开内容都保留。

首页显示顺序：

1. “返回工作”：有进行中的工作时出现，回到原分屏、焦点和工具布局。
2. 最近使用：会话、项目、目录统一摘要；快捷类型筛选，不在首屏堆满操作按钮。
3. 四个主要开始入口：终端 / 会话、项目、数据库、邮箱。其他能力通过“更多工具”发现。
4. 上次工作恢复：先展示内容数量和对象，允许选择恢复；沿用认证、取消、失败重试与清除记录。

最近项标明“已打开 / 已失效 / 需要认证”等真实状态。点击已打开项直接定位现有实例；打开失败显示原因和重试，不把 Tab 出现当成连接成功。移除最近记录与删除保存会话分别命名，提供不同的操作。

从两栏进入首页时暂存当前显示布局；首页显示为窗口级中间页面。返回工作原样恢复，首页期间收到的输出、通知和传输结果仍可到达对应内容。首页搜索、类型选择和滚动位置继续复用当前常驻 Welcome 的状态。

原型首页的最近内容为本次模拟 Tab，恢复按钮只选择并回到已打开内容；真实持久化恢复不在 demo 中接入。

## 10. 代表性用户流程

| 场景 | 操作过程 | 应观察到的布局 |
|---|---|---|
| 终端 + 文件 + 聊天 | 打开 SSH → 左侧文件 → Tao 聊天 → 固定 Tao | 文件明确绑定 SSH，聊天显示同一对象；空间不足时 Tao 以浮层暂开，文件偏好保留 |
| 混合类型并排 | 在 SSH 点“视图 → 左右并排” → 选 production → 点击数据库内容 | SSH 和数据库各显示一次；焦点转到数据库后，左侧变对象树、Tao 显示数据库上下文 |
| 代码开发 | 打开项目 → 项目树 → Git → 完整 Git 页面 → 返回项目 | 文件、Git 共用左面板；文件编辑状态、工作区内部 Tab 和运行输出保留 |
| 很多 Tab | 打开 30 个内容 → 总览 → 按类型筛选并搜主机 → Esc → 再选目标 | Esc 原样返回，确认目标才切换；所有内容仍可从总览找到 |
| 邮件通知 | Tao 通知 → 打开某封邮件 → 从邮件记录到便签 | 邮件完整阅读页承载账号/消息；便签在 Tao 打开，邮件选择保留 |
| 首页返回 | 两栏工作 → 点左上首页 → 看最近项目 → 返回工作 | 恢复两个内容、相同焦点和面板，而不是只恢复一个 Tab |
| 缩小窗口 | 固定文件面板与 Tao → 缩小 → 打开另一个工具 → 放大 | 临时浮层有唯一前景；偏好未被缩放覆盖，放大后恢复，内容不重连 |
| 关闭与取消 | 有未保存文件/草稿或运行任务 → 关闭内容 → 取消 | 回原内容，不丢状态；收起工具面板不触发业务关闭确认 |

## 11. 实现接点与共享契约建议

本节记录落点和约束，方便以后采纳；不形成任务拆分。

### 11.1 窗口外壳与业务模块的边界

| 现有接点 | 建议职责 | 必须保持的行为 |
|---|---|---|
| `MainLayout` / `ControlBar` | 全局区域、标题、首页切换、面板协调、内容两栏布局 | 窗口关闭检查、常驻内容的资源生命周期、真正的业务启动结果 |
| `TabBar` / `OpenTabsMenu` / `tabFilter` | 打开内容发现、排序、分组、筛选及总览入口 | 当前 `group/query/multi` 发现能力、重命名、关闭协议、可到达所有内容 |
| `appStore` / `sidebarRailPolicy` / `mainRailHostStore` | Tab 身份与活动状态继续权威；新增布局元数据与派生可见状态 | 保存配置不因视图分组改变，终端网格与输入锁单独保持 |
| `CodeWorkspaceTab` / `toolWindowLayout` | 暴露当前工作区工具入口与最小尺寸，保留内部布局所有权 | 编辑器分组、文件状态、撤销、LSP、运行/调试、已有六锚点与高级偏好 |
| `SftpSidebar` / Git / DB / Mail | 声明工具、最小尺寸和摘要能力；业务状态仍由原模块管理 | 传输、查询、提交、邮件草稿和账号身份不随 UI 重排重建 |
| `chatStore` / `taoHubStore` / notes / alerts | 消息、便签、通知各自权威；对统一宿主声明可见页与对象绑定 | 稳定 `chatTabId`、线程历史、提醒确认和实际动作目标 |
| window / capture 组件 | 平台窗口、拖动、捕获、原生输入继续使用实际适配层 | 不通过浏览器示意控件绕过 native API 或关闭确认 |

建议的窗口布局元数据：

```ts
// 建议新增的前端布局模型，不是已实现接口。
type ShellLayoutV1 = {
  version: 1;
  center: { mode: "content" | "home"; focusedPaneId: string | null };
  panes: Array<{ paneId: string; tabId: string }>;
  split: { preferredAxis: "left-right" | "top-bottom"; ratio: number } | null;
  left: { viewId: string | null; ownerTabId: string | null; width: number };
  tao: { open: boolean; presentation: "peek" | "pinned"; width: number };
  toolPrefsByContent: Record<string, { viewId: string | null; width?: number }>;
  viewGroups: Array<{ id: string; name: string; tabIds: string[] }>;
};
```

`tabId` 在运行中的打开内容集合内唯一；`paneId` 表示呈现位置。`ownerTabId = null` 用于全局会话导航。面板上下文取自聚焦内容，Git 仓库等进一步通过业务模块的上下文 ID 确定。布局元数据不复制连接参数、邮件正文、密钥、线程和便签数据。

运行时 pane / tab 关系不直接作为重启恢复依据。持久化按现有恢复记录中的稳定对象身份保存顺序、视图工作组和偏好；不可恢复的临时内容只保存适用的外观偏好，不猜测旧 `tabId` 指向新连接。内存中的原布局快照负责首页、专注和总览返回；它不是第二份业务状态。

“偏好布局”和“有效布局”分开：窗口尺寸变化只计算当前可见模式、临时浮层与排列方向；用户手动设置才写偏好。多个临时面板的前景归属是运行态，重启不恢复遮挡状态。旧数据缺失、损坏、含失效 ID 时返回安全默认单页，不自动关闭业务内容。

### 11.2 内容宿主和资源生命周期

每个内容实例仍由现有业务模块/服务持有，UI 布局不得靠反复卸载/挂载来移动实例。React key、PTY/连接 ID、`chatTabId`、工作区实例和传输 owner 保持稳定。宿主需支持可见性、几何尺寸、聚焦与摘要读取；这些通知不能隐式执行连接或业务命令。

内容能力建议包括 `canSplit`、`minSize`、`previewProvider`、`tools`、`closeGuard`、`canDetach`。能力缺失时提供可解释的回退。摘要读取是有界只读操作，失败仅影响相应卡片；异步摘要附对象版本/请求序号，避免旧对象响应覆盖新卡片。

复用当前 `react-resizable-panels`、工具宿主/portal、命令注册和 store；本设计不提出新增大型 UI 组件库。共享宿主究竟如何保持不同 native 渲染对象稳定，需要在实际接入前针对 RDP/VNC、CodeMirror 和 terminal 分别验证。无法保持实例的类型不得提前声明分屏可用。

### 11.3 迁移与恢复

旧侧栏分组折叠、面板宽度、Tao 位置/固定、工作区工具锚点、终端网格布局、最近内容记录都要兼容读取。新用户采用本稿默认；已有用户的显式布局以迁移映射为先，保留“恢复默认布局”入口和迁移后的解释。

`welcome` 保留身份但从业务 Tab 行移到固定首页入口；旧活动 welcome 映射到新首页。旧 Tab 筛选在首次迁移后仍可清除，当前项始终可到达。工作区已有六锚点偏好不能被单一左侧默认静默覆盖；选择旧高级布局时，也必须保持一份工具入口和一致焦点。

本方案主要是前端组织变更，优先复用现有 IPC、连接与持久化命令。只有实际预览适配需要而现有模块不能提供时再讨论接口扩展，本稿没有指定新增 Rust 命令。迁移写入新版本布局键，保留旧键以便版本回退；业务内容保存和重启恢复继续由现有系统完成。

## 14. 评审重点与设计边界

优先通过 demo 判断三件事：左侧工具与右侧 Tao 的分工是否符合实际使用习惯；预览卡片是否足以找到目标内容；固定首页是否让返回和继续工作更直接。密度、字体和默认展开项可以在保持上述组织的前提下微调。

尚需实证的点是各类型最小尺寸、原生内容移动后的实例稳定性、预览适配成本，以及真实用户更频繁使用哪种工作组合。这些是后续产品实现和体验验证的输入，不是本轮设计产物的完成障碍。

如果后续选择全部面板进入 Tao，需要重新设计 Tao 内的对象工具/助手分类、文件与聊天同时可见的方法和工作区内部工具映射；如果选择浮层优先，需要重新定义多浮层互斥、焦点及位置恢复。当前文档与 demo 均按 A 保持一致，没有把备选方案混入默认行为。
