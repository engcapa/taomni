# Taomni Horizon (Workspace Shell v3) 界面与交互重构详细设计

> **面向未来 One System 开发者平台的统一流线型工作空间架构**  
> 借鉴对象：**ZCode (智谱 ADE)** · **JetBrains Air** · **Claude Code Desktop** · **ChatGPT Desktop** · **Kiro Crew**

---

## 1. 重构背景与现状评估

### 1.1 `feat/ui-layout-refactor` 阶段性复盘
在 `feat/ui-layout-refactor` 分支中，Taomni 尝试从原有的单一扁平布局演进至“Workspace Shell”。虽然在代码层完成了 React 19 Activity 挂起、统一关闭协调器（Close Coordinator）以及六端跨平台回归测试，但阶段性的用户体验和交互测评**未能达到预期**，主要暴露出以下几个核心体验断层：

1. **Lanes（意图泳道）割裂日常开发心流**：
   * 原分支将标签机械地切割至 `home`, `connect`, `build`, `communicate`, `utility` 5 个独立泳道中。
   * **实际问题**：现代开发者的工作流是高度跨维度的（例如一边写代码 `build`，一边看测试机器的 SSH 终端 `connect`，一边在控制台查数据库 `build`，同时查收告警通知 `communicate`）。强行按泳道过滤标签，导致用户切换泳道时其他标签“隐身”，频繁迷失上下文，不得不依赖“Overview 总览”重新找标签。
2. **标题控制栏（ControlBar）过度拥挤与信息过载**：
   * 标题栏塞入了主菜单、Home 键、泳道标签列表、新建终端加号、快速切换（Quick Switcher）、上下文面板展开、Tao 开关、全量标签总览（带动态角标）、上下文动作插槽、更多下拉、窗口拖拽把手、截图、系统托盘和原生窗口三键。
   * **实际问题**：在标准分辨率（1920×1080 缩放 125%/150%）或分屏场景下，标题栏按钮密度极高，缺乏层次感，视觉噪点过多，严重干扰专注。
3. **Tao Hub 与 Context Panel 概念冲突与空间争夺**：
   * 架构上既存在右侧/底部的 `ContextPanelHost`（承载 SFTP、Git、工程树），又存在承载 Chat/Notes/Alerts 的 `Tao Hub`。
   * **实际问题**：两者在右侧互斥挤压，产生“打开 Tao 临时抑制 Host，关闭 Tao 恢复 Host”的复杂仲裁逻辑。用户心理模型产生困惑：“我右边到底在看工具还是在看 AI？”
4. **AI 与自动化割裂为“侧边聊天挂件”**：
   * 旧版 Tao 仅仅是一个挂在侧面的 Chat Drawer，与底层的 PTY 终端、代码编辑器、SFTP 和数据库并没有形成“意图输入 → 任务拆解 → 工具调用执行 → 代码/指令审查”的现代智能体闭环。

## 2. 外部优秀应用的设计借鉴与精髓提炼

为实现“清晰简洁、极度易用，且能支撑未来 One System 开发者平台”的目标，本案深入对标了业界顶尖产品：

### 2.1 ZCode (智谱 Agentic Development Environment)
* **核心精髓：任务与目标驱动（Goal & Task Centric）**
  * ZCode 不再将 IDE 局限于“文件编辑器”，而是重塑为“AI 智能体开发环境”。主界面直接映射 Agent 的认知与执行链路。
  * **布局启示**：左侧统一管理项目与长程任务（Task List / Goals），中间承载交互与执行轨迹，底部与右侧呈现环境足迹、工具调用授权与 Diff 变更审查。
  * **交互启示**：使用极简的 `@` 上下文绑定和 `/` 快捷指令，执行过程完全白盒化（透明呈现思考、命令行调用与产物），避免黑盒焦虑。

### 2.2 JetBrains Air (jetbrains.com/air)
* **核心精髓：极简 Fleet 镀铬层 + 开放式多智能体协同（Agent Swarm Orchestration）**
  * JetBrains 专为“智能体开发时代”打造的下一代工作台。
  * **布局启示**：极度克制的顶部命令中心（Top Command Bar），将复杂的各类工具栏收敛为一个居中全局入口（`Ctrl+K`）。
  * **架构启示**：开放的 Agent Conduit 协议（支持接入各类 ACP/MCP 智能体），原生提供多 Agent 并行调度面板，把 Agent 的变更直接映射到 IDE 原生的 Diff 工具和本地环境。

### 2.3 Claude Code Desktop
* **核心精髓：CLI-to-GUI 的流线型人机工效**
  * 将命令行的高效、纯粹感与桌面图形的直观可视化深度融合。
  * **交互启示**：零多余装饰（Zero-overhead Chrome），以键盘驱动为核心，命令回显、思考折叠流、交互式选项卡片自然融入上下文。

### 2.4 ChatGPT Desktop (Canvas Architecture)
* **核心精髓：双翼画布协同（Split-Canvas Architecture）**
  * 左翼对话与思考，右翼交互式工件（Canvas / Code / Artifact）。
  * **布局启示**：一键无缝折叠侧边栏，浮动工具条自适应内容，右翼工件支持全屏聚焦与侧边对比两种形态。

### 2.5 Kiro Crew (kirodotdev/KiroCrew)
* **核心精髓：持久化工作区记忆与无人值守自动化**
  * 跨会话的工作区记忆（Context Memory）、后台定时自动化（Cron/Heartbeat）与子智能体团队（Sub-agent Swarm）。
  * **扩展启示**：为未来 One System 平台提供了多 Agent 分工模式（架构师、编码员、测试员、审计员）的统一看板支撑。

## 5. 核心模块与交互细节重塑

### 5.1 居中全局命令中心（Command Center · `Ctrl+K`）
彻底淘汰原标题栏中散乱的“快速切换”、“更多”、“详情”按钮，统一为全局中心：
* **单快捷键直达**：任何界面下按 `Ctrl+K`（或 `Cmd+K`）唤起悬浮浮动面板。
* **多模态合一**：
  * **输入 `>`**：进入指令面板（执行重载、分屏、导出、切换主题、清理缓存等）。
  * **输入 `@`**：检索打开的标签、会话、项目文件、数据库表。
  * **输入 `#`**：唤起 Agent 预置 Prompt 或调度子智能体。
  * **默认输入**：模糊匹配所有会话、历史命令与功能，按方向键秒级直达。

### 5.2 统一协同侧翼（Companion Wing）
将原本打架的 `Tao Hub` 与 `Context Panel` 合二为一，提供三大模式选项卡：
1. **`🤖 智能体 / 任务流 (Agent & Tasks)`**：
   * **Goal-Oriented 视图**：展示当前正在执行的长程任务（如“升级 Spring Boot 3 并修复编译问题”）。
   * **透明白盒执行**：折叠的思考过程、Taomni 工具调用过程（如调用 SSH 运行测试、调用 DB 查询慢查询）、自动生成的代码 Diff 卡片（支持一键 Accept/Reject）。
2. **`🛠️ 会话工具 (Tools & Inspect)`**：
   * 自动匹配主工作区当前焦点的会话：
     * 主焦点是 SSH 终端时 → 显示 **内嵌 SFTP 文件树与传输进度**。
     * 主焦点是代码工作区时 → 显示 **Git 变更树与分支历史**。
     * 主焦点是数据库时 → 显示 **数据表 DDL 结构与索引详情**。
3. **`📝 随手记与传输 (Notes & Transfers)`**：
   * 会话无缝绑定的 Markdown 便签，支持拖拽终端文本生成临时代码片段。
   * 全局后台传输任务队列监控。

### 5.3 上下文标签流（Context Tabs）
* 标签不再受限于孤立的泳道，全部直观展示在主工作面顶部；
* 拥有小巧的彩色状态圆点指示（🟢 活动中 / 🟡 后台长任务运行中 / 🔴 异常告警）；
* 支持 **Pin 钉住核心标签**（钉住后标签收缩为紧凑图标，且免疫任何批量关闭操作）；
* 标签右键菜单统一收敛，且任何关闭操作依然经由 **Close Coordinator 事务引擎**，自动拦截未提交的 SQL、未保存代码和传输任务。

### 5.4 Zen 专注模式（Immersive Zen Mode）
* 按 **`F11`** 或点击顶栏极简图标即可进入 Zen 模式；
* 导轨（Rail）、协同侧翼（Companion Wing）、状态栏瞬间平滑收起，主画布享受 100% 满屏无干扰视界；
* 鼠标移动至屏幕左右边缘时，导轨或协同侧翼以透明亚克力阴影悬浮滑出，鼠标移开自动隐藏。

## 6. 面向未来 "One System" 开发者平台的扩展架构

```text
                     ┌─────────────────────────────────────────────────────────┐
                     │                 One System Developer Platform           │
                     └────────────────────────────┬────────────────────────────┘
                                                  │
                 ┌────────────────────────────────┴────────────────────────────────┐
                 ▼                                                                 ▼
   ┌───────────────────────────┐                                     ┌───────────────────────────┐
   │    Human-in-the-Loop      │                                     │    Agent Swarm Runtime    │
   │  (开发者交互控制面)       │                                     │  (自主智能体编排引擎)     │
   ├───────────────────────────┤                                     ├───────────────────────────┤
   │ • 顶层目标设定 (Goal Spec)│                                     │ • 任务拆解与调度 (DAG)    │
   │ • 权限门禁 (Auth Gates)   │                                     │ • 状态感知与上下文记忆    │
   │ • 代码/命令差异审查 (Diff)│                                     │ • 多子智能体并行隔离      │
   └─────────────┬─────────────┘                                     └─────────────┬─────────────┘
                 │                                                                 │
                 └────────────────────────────────┬────────────────────────────────┘
                                                  │
                                                  ▼
                     ┌─────────────────────────────────────────────────────────┐
                     │            Taomni Unified Core Capability Bus           │
                     │                 (MCP / Tool Registry)                   │
                     ├─────────────────────────────────────────────────────────┤
                     │  [Terminal/PTY] [SSH/SFTP] [Monaco] [Git] [DB Client]  │
                     └─────────────────────────────────────────────────────────┘
```

1. **底层能力工具化（Taomni as an MCP Server）**：
   * Taomni 原生的核心资产（经过生产环境验证的 SSH 隧道、PTY 交互、数据库连接池、SFTP 传输、Git 管理）被抽象为标准的工具接口，供内置或外挂的任何 LLM/Agent 自由调用。
2. **多智能体团队编排（Sub-agent Swarm）**：
   * 平台支持挂载多个专属职能的 Agent（如：`Planner` 负责调研方案，`Coder` 负责改代码，`Tester` 负责在终端执行验证，`DBA` 负责审核变更 DDL）。
   * 顶栏实时呈现所有 Agent 的在线与执行状态胶囊，协同翼可自由下钻至任一 Agent 的上下文。
3. **云地一体与环境穿透**：
   * 本地机器、远端云服务器、Docker 容器与 Kubernetes Pod 在统一工作区中平等视之，开发者无需再在终端工具、数据库客户端、IDE 和 AI 聊天软件之间来回切屏。
