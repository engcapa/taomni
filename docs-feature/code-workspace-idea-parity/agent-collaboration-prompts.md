# Taomni Code Workspace 与 IDEA 高度一致：总需求与重构提示词

本文件用于人工选择 agent 并分派 Code Workspace 与 IntelliJ IDEA 对齐工作。每个提示词都是
完整、自包含的任务正文：填写代码块开头的“本轮输入”，然后一次性复制整个代码块给 agent。
不再拼接公共前提、参数表和多个阶段提示词。

核心目标是通过持续评估、重构和能力完善，让 Taomni Code Workspace 在约定范围内的功能、UI 和交互
与目标 IDEA 高度一致。当前布局、组件、菜单、样式和交互模型都可以重构；验收以 IDEA 参照和用户
结果为准，同时保留已有正确能力及数据契约。总需求由持续更新的能力矩阵承载，工作包从真实差距
产生，验收证据再回到对应场景，形成下一轮完善的依据。

当前 P0 首次运行已完成，之后已有多轮 P1–P3。日常继续规划请直接复制
[固定 P1：自动选一张新卡做规划](handoff-p1-next.md)，无需填写输入；原带参数 P1 保留。

**本轮任务来源约束：** P0 必须把评估后的新差距写成 [独立任务板](backlog.md) 的
`ED-PARITY-xxx` 新卡。后续 P1 只从该板选卡做规划，P2 只从该板正式领取开发；P3/P4 接续同一卡。
`claudedocs/` 的旧板、旧 ID 和旧交接只作历史参照，不能混入新队列或继承其完成状态。
新任务的执行状态只在新板维护；index 与能力矩阵保存来源、链接和派生摘要。

## 1. 只选择一个入口

| 当前情况 | 使用 | 该 agent 负责到哪里 |
|---|---|---|
| 首次确定总需求，或改造后需要重新对比、补充能力与差距 | `P0 总体评估与能力矩阵` | 建立/增量更新矩阵与需求，并在独立任务板产出新卡；不改产品、不开发领取 |
| 希望不填参数，自动从 P0 新任务列表选一张卡规划 | [固定 P1](handoff-p1-next.md) | 自动选定一张卡，完成参考/设计/AC/V，生成明确板路径与 ID 的 P2 交接；不开发 |
| 还没有可领取的任务，或 IDEA 参考、设计、AC、任务边界不完整 | `P1 规划到可开发` | 从现状核对一直做到参考、设计和首个 ready 工作包；不改产品 |
| 已有准确任务板路径和可推进 ID，目标、参考及 AC 已充分 | `P2 开发并自验` | 领取一个工作包，完成实现、故障修复、集成和当前端必要验证 |
| 实现已完成，需要与实现者独立的代码、功能、UI 和交互结论 | `P3 独立验收` | 给出接受、需修改或证据阻塞结论；默认不改产品 |
| 已有失败、回归、中断交接、stale/build/runner/fixture/skill 问题 | `P4 恢复与诊断` | 先归因并修复授权范围内问题，再接回原任务，不重做整体盘点 |
| 希望同一个 agent 完成选定范围的规划、实现和验证 | `P5 端到端交付` | 按总需求完成本轮授权范围，复用已有矩阵和设计 |

选择规则：

1. 想知道“距离 IDEA 高度一致还缺什么”，用 `P0`；同一提示词可反复调用，默认增量更新已有矩阵。
2. 已知要完善的场景，但参考、设计或任务不充分，用 `P1`；已有可推进 ID 则直接用 `P2`。
3. 希望减少人工中转，用 `P5` 完成选定范围；需要独立结论时再给另一 agent 发 `P3`。
4. `P4` 仅在异常或中断时使用；正常实现中的修复和自验由 `P2/P5` 连续完成。
5. 一批改造完成、新参考出现或 IDEA 版本变化后，用 `P0` 重判受影响场景，不要求每个小改动都重跑
   整体评估。能力矩阵保存目标、差距与证据结论，任务板仍是开发状态唯一来源。

总体循环：`P0 总需求/能力矩阵与新任务卡 → P1 选一张卡规划 → P2 领取开发 → P3 验收 → P0 增量更新`。

选定差距后，多 agent 路线是 `P1 → P2 → P3（需要独立复核时）`；单 agent 路线是 `P5`。
两条路线择一，已有充分设计和证据就直接接续，不重复执行。

每个 agent 只执行收到的一个完整提示词，不自行调度、委派或启动下一角色。跨 agent 交接默认使用
任务板、设计、参考包和 QA 报告中的持久材料；聊天摘要只保留准确路径、ID、结论和未完成条件。

## 2. 复制与填写

- 只复制所选提示词的整个 `text` 代码块，不需要复制本节或其他提示词。
- 填写范围和材料入口即可；其余 `<...>` 可写“沿用已有材料，由 agent 核对”，不必手工重抄已有契约。
- “修改权限”必须明确。只读、文档、产品代码、测试设施、任务状态、提交/推送是不同权限。
- 附件或外部报告可直接追加在代码块之后；仓库内材料优先填写准确相对路径。
- 每个 Prompt 前有选型表，在工具中手工选好 agent、模型和 effort，再复制代码块；正文不会自动切换模型。
- 选型依据为 [coding-agent-model-selection.md](coding-agent-model-selection.md)，结合用户最新确认的资源：
  Codex（模型沿用该文档中的 Astra/Sol/Terra/Luna）、agy + Gemini 3.8 Flash、OpenCode + Muse Spark 1.3 /
  GLM-5.3-Flash / DeepSeek-Flash、Claude Code + DeepSeek-Flash。不扩展到其他工具或未确认的模型。
- 每表按“能力优先，成本次之”给出职责匹配建议，第一行是能力首选。沿用选型文档的角色与档位依据，
  不沿用其中成本优先的排序或历史 P 编号；本轮没有重新进行模型横向实测或价格核查。
- DeepSeek-Flash 在该文档中对应 V4.1 Flash（`deepseek-flash`）；实际接入显示不同版本时记录真实 ID，
  不静默替换。不同工具同名 effort 不等价，使用实际 provider 支持的档位；Muse 默认指 Standard。
- 视觉职责要求模型收到真实图像，并能获取对应桌面证据。DeepSeek 作为文字专项备选，不独立签发视觉
  结论；无需为使用全部模型而拆分任务，Luna 等轻量组合也不默认承担开放式总需求或复杂重构。

## 3. 完整提示词

### P0 总体评估与能力矩阵

用于首次建立“与 IDEA 高度一致”的总需求、现状基线和能力矩阵，也用于后续增量对比。首次运行时
必须先把 Taomni 当前 UI 和真实交互完整打印为可复查基线，再与 IDEA 逐场景比较；现有实现只是被
评估对象，不能限制后续重构。P0 负责创建独立新卡，P1 只细化从新任务板选出的工作包。重复执行的是同一 skill 的 audit/plan
入口，无需另建 skill。

| 推荐 | Agent | 模型 | Effort | 使用边界 |
|---|---|---|---|---|
| 能力首选 | Codex | GPT-6 Astra | xhigh | 总需求、跨模块事实冲突、长期增量矩阵与缺口归因 |
| 强推理备选 | Codex | GPT-5.6 Sol | high | 生产调用链和证据清晰，仍需完整需求判断 |
| 多模态备选 | OpenCode | Muse Spark 1.3 Standard | high | 大量图像、状态和文字材料联合比较 |
| 多模态备选 | Antigravity（agy） | Gemini 3.8 Flash | High | IDEA 参照及 UI 差异占主要工作量 |

首次整体评估覆盖项目树、标签页/分屏、编辑、导航、搜索替换、补全/诊断、重构/格式化、Git、

不能用源码或组件结构代替。随后使用同一场景、同一 fixture 和匹配环境记录 IDEA 参照；两侧缺一不可，
否则该维度只能是待验证或不可比较。

能力矩阵的每个场景还至少包括：
- 稳定 ID、能力域、用户场景及 IDEA 期望结果；
- 功能、视觉、交互三个独立结论：已对齐/部分对齐/未实现/待验证/不可比较；
- Taomni 生产入口、调用链、状态 owner、IPC/provider 和用户观察点；
- IDEA 参考的准确路径、build/环境和状态/步骤；缺少则明确待采；
- Taomni 证据路径、源码/case/runner/config/build/平台/模式身份及 current/historical/stale/unverified；
- 差异依据与性质：确认产品缺陷、能力缺失、视觉/交互体验差异、纯证据缺口或待归因风险；
- 需求结果、必须保留契约、优先级及理由、依赖、关联设计和任务板路径/ID；
- 上次结论、本次变化及其依据；未变项只保留原检查时间，不刷新成新通过。

能力缺失与体验差异要形成可追踪需求：写清目标行为、当前差距、影响、建议重构或完善方向和可观察
验收结果。允许重组当前布局、组件、动作和交互，不把保留现状当约束；保存/撤销/取消/恢复、正确能力、
数据兼容以及 Windows/macOS/Linux 支持必须保留。纯证据缺口给最小补证动作，不凭空登记产品 bug。

逐项核对生产代码和证据，不依赖文档标题或 done 数。证据 stale 不等于产品退化，缺真实双侧观测时
不能给出已对齐；功能测试不替代视觉或交互证据。没有明确分母及逐项支持时不输出总体对齐百分比；
新增、拆分、合并或移出场景需记录原因和 ID 映射，不能靠缩小分母提高一致程度。

在授权范围内完成当前 Taomni 与目标 IDEA 的最小充分双侧采样。需要桌面时确认目标窗口、焦点及隔离
fixture；锁屏不得自动解锁。无法采样时，必须打印“当前 UI/交互基线缺失”，列出缺失状态、具体采样
步骤和阻塞的矩阵维度，不能输出已对齐。计划中的额外检查始终标为未执行。未经授权不修改产品、测试

把本轮新增需求、仍存差距、已由新证据关闭的差距、证据失效和待决目标写回同一有效矩阵及总需求入口。
关联后续实现/验收材料，保留旧结论依据；总需求是目标与差异来源，开发状态仍从任务板读取，不能建立

最终交付：总需求/矩阵路径；本轮覆盖分母和边界；增量变更摘要与证据；按用户价值、影响范围、重构

#### P0 首次运行与非首次运行的填写方式

首次运行时 `index.md` 可以不存在。agent 必须先按 `$code-workspace-idea-parity` 的持久交接规则创建
`docs-feature/code-workspace-idea-parity/index.md`，再创建或更新总需求/能力矩阵和独立 backlog.md；不能因为入口文件
缺失而停止，也不能伪造“已有矩阵”。首次运行必须输出 Taomni 当前 UI/交互基线和 IDEA 对照基线。

完成一轮改造后的后续调用使用下面这份增量模板。它只复核变化及其受影响场景，不重新盘点未变化的全部范围，
但仍把结果写回同一总需求矩阵，并保留历史结论和证据身份。
已有首次 P0 却未产独立新卡时，按增量入口核对后续交付后补录；不能要求重跑首次评估或整板复制旧卡。

## 5. 完成判定

| 维度 | 判定依据 |
|---|---|
| 功能 | 真实入口产生预期结果，错误、取消、保存、撤销及恢复路径满足契约 |
| UI | 匹配环境下有双侧关键状态；布局、几何、密度和视觉角色逐项有依据 |
| 交互 | 真实鼠键、焦点、选区、菜单、打开/关闭和恢复序列满足契约 |
| 集成与回归 | 最终组合代码的相关消费者和连续操作已验证，无未解决的本轮新增退化 |
| 证据 | 来源、模式和环境可识别，current、historical、stale、skip 与未验证分开 |

仅当声明范围内的目标与保留契约满足，或有限差异已被明确接受，才能称该工作包完成。当前端完成不
等于三端完成；browser 不等于 native；参考包完成不等于 Taomni 已对齐；任务 done 不等于证据 current。
