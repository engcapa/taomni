# Code Workspace IDEA 对齐

以当前生产能力为开发基础，以用户选择的 IDEA 体验为目标。当前布局、组件、菜单、快捷键和流程都可以重构；复用代码是成本判断，不是保留当前 UI 的约束。使用中文交接，兼容 Windows、macOS、Linux。

## 按请求选入口

模式是自然语言用法，不是 CLI。一次只加载当前模式需要的材料。

| 入口 | 做什么 | 不隐含什么 |
|---|---|---|
| `audit <范围>` | 核对范围内生产入口、现有文档与证据，分类差距 | 不默认全编辑器盘点、运行全套测试或改代码 |
| `plan <范围>` | 形成可开发工作包、参照需求、UI 目标与验证选择 | 不自动领取或实施；仅要求聊天规划时不落盘 |
| `next [任务/范围]` | 完成一个可推进的工作包；已有明确规格直接接续 | 不为了改一个功能先审计全部能力 |
| `verify <范围>` | 针对已实现内容补足本次必要证据 | 不将缺证据直接认定为代码缺陷 |
| `status <范围>` | 汇总已有实现、比较结论、当前证据、缺口和下一步 | 不执行测试或改任务状态 |

用户只要求创建、修改或测试这套 skill 时，停留在 skill 文件和工具的范围；不建立真实能力清单、产品 backlog 或启动 IDEA/Taomni。示例任务不代表已领取。

## 定位与接续

1. 读取 AGENTS，记录 HEAD、工作区改动和本次范围。优先沿用会话明确的任务、基线、IDEA build、UI 决定与授权。
2. 用户指定板/ID 优先；否则查找该能力已关联的任务和有效索引。通过 `rg` 按能力/动作/符号发现相关材料，包括 `claudedocs/`、`docs-feature/`、`docs-issue/` 和入库 `evidence/`。不要按日期最大或历史 done 数选择任务板。
3. 用生产 caller 核对受影响路径，读设计的当前有效契约及其后续修订。只在最近代码变化或缺口影响结论时扩大调研；保存过的行号只供定位。
4. 没有有效任务且用户授权开发时，可按本工作流的计划阶段建立一个小工作包，再交给开发 skill；这是该开发请求中的正常步骤。无可做差距时报告事实，不重开 done 来制造工作。需要用户决定的实质目标冲突保持待决，继续独立工作。

维护能力索引、增量规划或报告时读取 [工作包与证据接续](references/work-packages.md)。仅在请求需要持久交接时创建索引，默认 `docs-feature/code-workspace-idea-parity/index.md`；任务板是开发状态唯一来源，索引保存链接与派生摘要，不另造状态引擎。

## 场景驱动开发

将目标写成前置条件、入口、操作、可见状态、最终结果与恢复路径。涉及可见变化时读取 [UI 与交互对齐](references/ui-alignment.md)，使用 `idea-reference` 获取或复用匹配的参照；简单已观测行为无需重采整个 IDEA。

区分已有且满足、已有但待验证、行为缺陷、视觉/交互差异、新增能力和不可比较。仅修复有证据的差距；允许为目标重构组件、布局或动作组织，保留无关能力和数据契约。

开发交接同时携带“本次有意改变的行为”和“受影响但必须继续正常的行为”，后者也有可观察断言与改前依据。按 [既有行为保护](../qa-ui-auto/references/regression-protection.md) 检查共享调用方、入口和连续操作；允许 UI 重构不等于允许丢掉已有能力。本次造成的相邻退化由当前任务处理，不能仅因新目标通过就交付。

| 当前需要 | 接续 skill |
|---|---|
| IDEA 布局、操作或源码依据 | `idea-reference` |
| 新增能力、布局/交互改版 | `feature-design`；规格已充分时复用，不重复设计 |
| 已证实错误的修复设计 | `issue-design`；直接执行已有修复无需先补长文档 |
| 开发一个已定义工作包 | `code-workspace-idea-task`，传完整板路径和任务 ID |
| 选择/执行验证、解释耗时或证据 | `qa-ui-auto`，传 AC、改动范围和实际场景 |

相关 skill 不可发现但项目文件存在时，读取其 `SKILL.md`；不存在则沿用可用工具完成相同范围并说明缺口，不编造调用接口。

## 验证与收尾

先用 [高效验证选择](../qa-ui-auto/references/efficient-verification.md) 制定最小充分验证：开发迭代用定向单测/挂载或浏览器；相关代码稳定后按本轮场景集中构建原生 QA。需要原生才编译，不把每次截图、CSS 调整或测试编辑变成一次 Cargo 构建。涉及原生独有行为应尽早做一个区分性探针，避免最后才发现错误路线。

一次运行可覆盖多个验收或证据种类，明确各自观察点。功能、交互、视觉、性能分别判断；未运行不算通过。目标 IDEA 比较通过需要匹配的真实参照与 Taomni 观测，普通 validator exit 0 不等于 matched。历史豁免保留其范围和上限，不自动推广到新任务。

仅当有新改动、失败或尚未证明的要求时重复/扩大测试。完成已授权的必要工作后交付，不额外增加全量回归、发布门禁或最终审批。报告任务/范围、结果、UI 差异、实际测试与构建次数、平台/前端模式和剩余缺口；提交、推送等遵从用户请求。

## 用法

- `使用 $code-workspace-idea-parity plan，规划指定能力的 IDEA UI 与交互改版，先不实施。`
- `使用 $code-workspace-idea-parity next，按给定任务板交付一个工作包，允许重构现有交互。`
- `使用 $code-workspace-idea-parity verify，补指定场景的证据，先检查是否需要重新构建。`
