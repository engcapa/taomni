# 工作包与证据接续

## 能力索引（被请求时才建立）

稳定标识代表用户能力/场景，不代表某一轮修复。复用已有编号；索引关联当前生产入口、有效规格、先后任务、IDEA 参照、QA cases 和证据。不要在 skill 内写入实时完成数量或待开发清单。

每项分别记录功能实现、交互比较、视觉比较、性能测量与证据适用范围。没有逐场景分母时不输出对齐百分比。对旧文档的“待执行”和后来修复的“通过”，用生产提交和证据身份解释先后，不按文件标题选权威。

证据身份包括源码内容（含相关未提交变化）、case/runner、build、前端模式、OS/WebView、provider、fixture 与设置。旧报告保留为历史；当前身份不匹配是待复验，不等于产品有 bug。原始报告本机缺失时记录获取位置与摘要来源，不制造新的 PASS。

## 一个工作包应有的内容

| 内容 | 要求 |
|---|---|
| 目标 | 一个可演示的用户结果；正常与关键退出/恢复路径 |
| 当前基础 | 实际生产入口与职责；受影响已有能力 |
| 对齐依据 | IDEA 参考包的版本/场景/关键状态；未知项独立列出 |
| UI/交互变化 | 哪些入口、布局、焦点/快捷键或状态变化；允许必要组件重构 |
| 保留契约 | 受影响的既有用户行为、消费者和数据契约；有可观察断言、改前依据与改后结果，不能只写“保持原功能” |
| 实施 | 文件/符号职责、依赖、集成点；共享组件变化列消费者回归 |
| 验收 | 稳定 AC ID、动作与结果；区分新增/有意改变/保留行为，覆盖相关视觉、交互和功能 |
| 验证选择 | 每个 AC 的最便宜充分层级；迭代检查、本轮收尾、集成责任与未运行项 |

不是每张卡都需要所有证据种类或完整设计长文。简单外观调整可复用截图/几何对照与当前端 WebView smoke；新状态机、事务或 OS 边界才增加对应回归。多个证据种类可以链接同一次执行，不重复启动应用证明同一结果。

回归选择遵循 [既有行为保护](../../qa-ui-auto/references/regression-protection.md)。未受影响的产品能力不盘点；实际受影响的其他 feature/旧卡必须进入消费者检查。基线缺失与基线失败分开记录，本次新增退化不能以“相邻卡”排除。对共享交互重构，计划在有实质风险的切换点快速检查，并在最终组合代码上验证相关行为。

已有任务的 required evidence 不能为消除失败而减掉。如果旧合同的 UI 限制或验证范围与当前用户授权冲突，先完成具体差异说明和可审阅修订；已有授权足够时同步修订相关规格与映射再实施，保留原始失败和历史范围。新任务在设计阶段按风险选择要求，不机械复制旧卡的全套层级。

## 任务板选择

交给开发 skill 时携带 `board path + task ID + spec + reference + verification selection`。每条 task-board 命令带 `--doc`。发现多个板含相同能力，核对后续修复/替代关系，不自动选择日期最新的板或脚本默认板。

历史任务状态保留；新观察到的差距链接旧任务并去重。板已完成而用户仅问状态时直接报告；用户要求继续开发时，基于当前证据规划新的小任务，不能重领 done 或伪造依赖完成。

## 交接断点

保存本次源码基线、受影响文件、当前有效参照/规格、已执行检查与命令、构建身份及待完成项。接续时先看变化，不重跑没有变化且仍有效的结果。当前 QA 全局 fingerprint 导致旧结果 stale 时如实处理；影响分析可以选择最小复验集，但不能把旧 receipt 改成当前 PASS。

若用户只要求 skill 建设，以上均为未来运行规则；不预填任何真实任务或能力状态。
