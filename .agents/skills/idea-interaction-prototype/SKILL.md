# IDEA 交互原型

交付基于真实 IDEA 观测的交互原型，供 coding agent 实现任务卡中的用户行为。仅创建本技能时不启动 IDEA；执行原型任务时才运行下面的流程。

## 输入与范围

- 接受任务板路径、任务 ID、IDEA 版本、可选应用路径、可选 Java SDK 路径、输出位置和 `force`（或“强制重新生成”）。这些是自然语言参数，不是假定存在的 CLI。
- 默认任务板为 `claudedocs/code-workspace-idea-prototype-backlog-2026-09.md`，也支持相同语义的其他任务卡。版本由用户本次明确指定，否则取卡片及链接规格要求；默认任务板要求 2026.2.x。精确 build 要求不得放宽。用户指定版本与规格冲突时记录偏离，不能声称满足原规格版本的验收。
- 原始开发审计任务板 `claudedocs/code-workspace-idea-parity-backlog-2026-09-audit.md` 只作来源参考，不直接修改；原型领取、路径和状态只写入独立原型 backlog。用户提供其他开发任务板作为来源时，同样先派生新的原型 backlog。
- 每次默认处理一张卡。读任务描述、链接规格与验收，将可观察功能拆为场景。只覆盖本卡交互，无需复制整个 IDEA。
- 使用 [任务卡与产物合同](references/task-and-artifacts.md) 读取、领取和回填原型字段。原型生命周期独立于开发生命周期，不调用开发任务脚本的 claim/update 来领取原型，不改变顶层开发状态、owner、依赖或证据。

## 1. 筛选与领取

1. 未指定 ID 时，按优先级、板中顺序寻找 `prototype.status != done` 且没有其他执行者活动领取的行为卡。缺少原型字段视为 `pending`，先补路径与状态。开发依赖不自动阻止独立的 IDEA 采样；实际缺少必要 fixture 或规格时记录阻塞。
2. 指定卡已 `done` 且没有 `force` 时，返回现有 HTML 路径并跳过。即使产物丢失，也报告缺失而不偷偷重生成。`force` 只豁免 done 检查，不豁免版本、取证、验证或他人领取。
3. 纯校验器、构建门禁等没有 IDEA 用户交互的卡不捏造原型：记 `blocked` 及理由；自动选择时继续找行为卡。混合卡应写明交互范围和不能由原型证明的后台验收。
4. 写入原型 owner、开始时间和 `in_progress`，回读确认。写前重读卡片，保留其他 agent 的更新；发现领取冲突则停止该卡。无法判断旧领取是否已结束时不抢占。

## 2. 准备本地 IDEA 与 Java 工程

1. 先发现可用桌面控制、截图工具及本机 IDEA 进程、可执行路径、版本。可结合进程路径、JetBrains Toolbox 安装信息、`product-info.json` 与应用 About 页面确认，不能仅看窗口标题猜版本。只使用当前会话真实可用的工具，不编造桌面自动化 API。
2. 已启动的目标版本直接复用，在独立项目窗口打开 fixture；只有其他版本运行时保留它们，另启动要求的版本。不关闭用户窗口或丢弃未保存内容。
3. 未启动时从已确认路径启动；找不到安装或路径不明确时，要求用户提供 IDEA 可执行文件／macOS 应用路径。版本未指定且无规格依据时一并询问版本。不要自行下载、升级或用别的版本替代。
4. Windows 用原生 PowerShell 启动，路径作为参数处理，不拼接到另一层 shell；IDEA 是用户需要看见和操作的目标应用，可正常显示窗口，辅助进程保持隐藏。macOS 使用目标 `.app`，Linux 使用实际启动入口。启动后再次核对实际窗口和 About 完整版本、build、edition。
5. Java 工程由 agent 根据任务在隔离目录自行准备，例如系统临时目录下的 `taomni-idea-prototype/<task>/<run>/project`。检查本地 JDK、`JAVA_HOME` 和 `java`/`javac`，优先使用满足规格的已有 SDK；无法确定或缺少合适 SDK 时可要求用户指定路径。IDEA 的 JetBrains Runtime 不等于项目 Java SDK。
6. 优先用不依赖联网的最小 Java 工程；仅在任务需要时使用 Maven/Gradle、多模块或额外库。准备足以触发本卡行为的源码、错误或引用关系。保存可重建的初始源码、目录树、编码/EOL、文件 hash、构建配置和必要依赖版本；不要让用户准备工程。
7. 在 IDEA 中实际打开该工程，设置并核实 Project SDK、语言级别、keymap、相关插件及编辑设置；等待导入、索引与语义服务就绪。记录真实 SDK 版本和就绪依据。保存项目路径别名，证据避免包含个人目录信息。
8. 桌面控制、截图权限、目标版本、SDK 或项目导入无法满足时，完成不依赖这些条件的场景整理，记录 `blocked` 和具体缺口并请求必要信息。没有实测不能继续生成“已验证的 IDEA 等效原型”。

## 3. 按卡操作并截图取证

1. 建立“验收 ID → 场景 → 前置内容/设置 → IDEA 动作 → 观察点”映射。先复现正常路径，再覆盖卡片要求的取消、撤销/重做、焦点、键盘和失败恢复路径。
2. 通过真实 IDEA 菜单、快捷键或可见控件执行动作，记录 action 名称、实际快捷键/菜单路径和输入。使用当前 keymap，不能把某一平台的快捷键当作三端通用。
3. 每个有意义的状态转换保存原始截图：初始界面、菜单/弹窗/候选列表、选择/预览、提交结果、撤销/取消结果。连续帧按步骤编号，截图录制至少包含这组有序图片；用户另要求视频时再录屏，视频不能替代关键截图。
4. 将截图与步骤、时间、窗口尺寸、缩放、光标/选区、焦点、文本变化对应起来；截图看不出的字节/EOL、磁盘内容、undo 行为需另行观察和记录，不能从画面推断。重置 fixture 后至少复跑正常与撤销路径一次（不适用时说明）。
5. 保留原始证据；裁剪或标注图必须另存并链接原图。禁止用 HTML 截图、合成图或文档插图冒充 IDEA 观测。
6. 不能触发的失败或 IDEA 不存在的 Taomni 内部状态如实标为未观测/安全扩展，不虚构 IDEA 的错误文案和处理过程。将实测事实、卡片期望、推测明确分开。

## 4. 生成单 HTML 交互原型

1. 按观测实现可点击、可键盘操作的界面状态机，重现本卡相关布局、控件、文案、展开收起、选中、焦点、菜单/弹窗、文本结果和历史行为。截图是视觉参照，不能只做截图轮播或热点跳页充当等效交互。
2. 最终交付严格为一个 `.html`，内联 CSS、JavaScript、必要图标与图片（data URI）；无 CDN、远程字体、外部 JS/CSS、构建步骤或服务端依赖。双击 `file://` 即可使用，不用 `fetch` 读取旁边的 JSON 或 fixture。
3. 用内存数据模拟本卡需要的编辑与文件状态，不触碰用户真实文件。浏览器无法真实等效的原生 IME、系统剪贴板、磁盘故障、索引引擎或性能，只可显示有证据的交互状态；在说明中明确模拟边界，不能声称验证这些原生能力。
4. 提供初始状态重置和场景选择，确保各路径可以重复操作。仅在控件适用且获得焦点时处理快捷键；如被浏览器/系统拦截，提供可达的菜单入口并记明限制。
5. 在 HTML 中内嵌可展开的“实现参考”区及 `application/json` 数据块，包含任务/验收 ID、IDEA build、OS、SDK、场景步骤、状态转换、关联截图、初始源码、实测与模拟边界。使 coding agent 仅拿到 HTML 也能理解操作和状态，不必找外部截图；原始取证仍按合同另存。该区与 IDEA 仿真界面分离，不把取证元数据塞入仿真的产品流程。
6. 数据作为文本安全嵌入，转义 HTML/脚本结束标记；不要把 fixture 文本解释为可执行脚本。使用清晰命名的 action/state 和稳定控件标识，方便 coding agent 对照实现。

## 5. 验证与回填

- 用本机可用的真实浏览器打开最终 HTML；需要浏览器自动化时使用可用的 `playwright` 技能。验证 `file://` 加载、离线自包含、无异常、每个要求场景的鼠标与键盘操作、取消/撤销和重置。仅有源码检查不能记交互验证通过。
- 截取 HTML 对应状态，与 IDEA 原始截图逐场景对照；分别记录视觉差异、交互差异和模拟限制。实际浏览器未能执行或核心路径未覆盖时不能标 `done`。
- 只有目标版本 IDEA 已实测、必需截图齐备、交互范围有证据映射、单 HTML 可用且浏览器验证通过，才将 `prototype.status` 写为 `done`，补全版本、验证时间、证据路径与 HTML hash。原型 done 仅表示原型交付，不表示 Taomni 已实现或全部开发验收通过。
- 强制重生成先另存新 run，保留旧 HTML 与证据；新产物通过后再切换卡片路径，失败保留旧路径并明确本次状态与原因。不得用旧结果冒充本次成功。
- 最后给出任务 ID、HTML 链接、IDEA 版本/build、取证位置、验证结论和限制。Windows、Linux、macOS 分开记录；本机实测不推广到另外两端。不因本任务关闭用户原有 IDEA 会话。

## 调用示例

- `使用 $idea-interaction-prototype，为 ED-AUDIT-007 在 IDEA 2026.2 中采样并生成原型。`
- `使用 $idea-interaction-prototype，从默认任务板领取一个原型未 done 的行为卡；IDEA 路径为 D:\Apps\IDEA\bin\idea64.exe，Java SDK 为 D:\SDK\jdk-21。`
- `使用 $idea-interaction-prototype，强制重新生成 ED-AUDIT-009 的原型，保留上一版。`
