# Skill 实跑验收

用于实质 workflow/runner 重构或用户要求的 skill E2E。小幅文案修正只复核受影响指令，不重新开发一个产品功能。

## 执行

1. 沿用用户范围、已有工作包和原始材料，不重新选题或重领 done 卡。复杂流程在可用且获授权时做独立 agent 评估，给真实请求和入口，不透露预期答案；没有独立评估则如实说明。
2. 从 AGENTS 和 skill 路由实际接续，按 [高效验证](efficient-verification.md) 选择目标与受影响保留行为的并集。验证本次改变的入口；通用 QA 改动也检查相关非 IDEA 用法，不默认全 App 测试。IDEA 采样复用 [capture](../../idea-reference/references/capture.md) 的桌面与焦点规则。
3. 发现摩擦时复现原因：agent 未遵循已有规则则纠正执行，指令/工具缺陷则修 md、脚本或配置，再验证同一触发。脚本新增行为补有意义的测试；不能只在对话绕过，也不为单次现象累加泛化要求。
4. 按 [verification](verification.md) 判断证据时效，独立检查 build 是否可复用。仅 planner/报告工具变更用设施测试及真实 CLI 验收；动作执行变化才重跑受影响模式。stale 报告不代表需要重编，旧 receipt 不改写。当前 native 确属验收要求时仍需补齐。

## 完成与交接

完成需证明：后续 agent 能找到契约和可执行命令、选择充分而聚焦的检查、保留目标以外的受影响行为，并复验已修复的 skill/工具问题。UI 对齐分别判断功能、交互和视觉；产品通过或静态 validator 通过均不能单独证明 skill 可用。

复用未变部分的有效评估，只复核后续改动影响的项。简短交接包含范围/输入身份、实际命令与结果、构建/复用和耗时、发现→修复→复验，以及当前/历史/stale/skip/未验证边界。独立只读评估不能写成独立产品 E2E；锁屏 browser 通过不能证明 native/IDEA/物理输入。

过程、案例时间线、截图和原始日志放任务报告；需跨 agent 保留的结论放用户选择的仓库文档，原始工件留在 ignored QA report root。Skill 只保留可复用规则与设施，不存本次验收记录，不要求每次运行生成独立长报告。
