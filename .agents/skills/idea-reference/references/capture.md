# 场景采样

1. 把用户请求或任务验收拆成必要场景和观察字段，先正常路径，再本场景有关的取消、undo、焦点或错误恢复。能共用环境/fixture 的场景一次准备，独立重置初始状态。
2. 发现真实可用的桌面控制与截图工具。computer use 适合探索；可靠快捷键、可访问性或既有 OS 自动化适合重复动作。浏览器 Playwright 不等于 Java 桌面控制，不编造工具 API。
3. 用安装的 `product-info.json`、进程路径和 About 核对实际 version/build/edition。复用匹配进程，在独立 fixture 项目窗口采样；不关闭用户窗口、替换配置或丢弃内容。缺少版本/权限时说明具体缺口，继续独立的场景/源码整理；不自动下载升级 IDEA。
4. agent 自备可重建隔离工程和初始文件。按语言核对 SDK（IDE 自带 Runtime 不等于项目 SDK）、插件、provider、导入和索引就绪。简单行为用离线最小工程；只有场景确实依赖时才采用多模块、大工程或联网依赖。原工程如需复现使用隔离副本。
5. 记录 OS、窗口客户区、屏幕缩放/DPR、主题、locale、字体/字号、keymap及实际绑定。平台特殊快捷键单独记录。
6. 通过真实 UI 动作执行，每个有意义的转换保存原图和对应 step：初始、打开菜单/候选、选择/说明/预览、提交、取消或撤销。拖拽和时序难以表达时补录屏，不以视频代替关键状态。
7. 记录焦点、caret/selection、滚动、文本及文件结果。正常与主要恢复路径重置后复跑一次确认可重复；只重采不稳定/缺失部分。
8. 查源码前先明确待解问题。沿动作名定位注册/启用条件/实现与行为测试，记录版本和符号。源码分支与实测不一致时查设置/插件/版本，不默默覆盖实测。目标不存在的内部错误状态记为 Taomni 适配，不虚构 IDEA 行为。

Windows 启动目标应用使用原生 PowerShell 参数；辅助进程隐藏。其他平台使用实际应用入口。临时 fixture 使用独立目录，清理只针对本轮资源。多个场景共享同一 UI 控制会话时顺序采样，避免抢焦点；不因速度改变用户的工作环境。

没有工具或目标安装时不能产出“实测完成”的参考包。可以交付源码依据和可执行手工步骤；说明缺口后仅请求必需信息，已有路径/版本与授权不重复询问。
