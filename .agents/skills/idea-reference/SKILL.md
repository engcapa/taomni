# IDEA 场景参照

以用户能观察的 IDEA 行为和界面为参照；源码解释隐藏规则，文档帮助定位功能。事实、源码依据、推断和拟议适配分开记录。

## 输入与范围

接受场景/能力/任务、版本/build、平台、可选 IDEA/SDK 路径、现有参考包和输出位置。用户指定基线优先，其次所选任务有效规格；现有旧契约可能固定 2026.2.x，但不能将该版本写成所有新任务的永久默认。版本冲突须解释，不能用已安装旧版本冒充目标版本。

仅创建/修改本 skill 不启动采样。用户要求查源码时只查问题相关源码；要求采样时只处理给定场景。无场景时先从任务验收提炼必要动作，不遍历整个 IDE。

## 复用优先

先核对现有参照的版本、平台、设置、fixture、关键状态和原始产物。有效材料可被多个任务引用，不必随 Taomni 代码变动重采 IDEA。参照失效或场景缺失才补采受影响部分。CLI 格式化结果只证明该文件的格式化，不证明 GUI 菜单、焦点或快捷键。

执行真实操作前读 [采样流程](references/capture.md)。交付前读 [参考包合同](references/reference-contract.md)。需要源代码时定位对应版本的开源仓库/tag/commit及测试；不默认克隆/构建整个 IntelliJ 平台，不假设商业插件全部公开。

## UI 是一等产物

记录布局、密度、字体、图标、颜色角色、弹窗位置以及正常/选中/失焦/禁用/加载/失败等本场景状态。操作序列同时记录焦点、选区、文本/文件变化和取消/撤销。截图无法证明的事实用独立结果观察补充，不从像素猜磁盘或历史语义。

需要呈现新方案时，可将参照交给 `feature-design` 制作图稿或原型；本 skill 可在用户要求时做最小参考原型，明确模拟边界。HTML 自包含仅在需要离线交接时采用，不强制每个场景产出 HTML/视频。原图、裁剪标注、原型截图分开保存，不能互相冒充。

## 收尾

交付实际基线、场景步骤、原始证据及参考摘要路径、源码定位、未观测项和可复用范围。原始采样默认位于被忽略的 `qa-ui-auto-report/idea-reference/<scenario>/<run>/`；可交接摘要在用户所选设计目录或 `docs-feature/code-workspace-idea-parity/references/`，用相对链接与获取说明指向原始包。

摘要须按参考包合同脱离聊天即可复现，区分有效采样、输入污染与未观测项。

这里只记录参照就绪状态，不修改产品卡的 owner/done。需要正式 IDEA 比较时，由 `qa-ui-auto` 用双侧观测生成现有比较记录；先核对所用 schema/validator 支持的版本。合法参考包、源码解释和 prototype 均不能单独签发产品对齐通过。
